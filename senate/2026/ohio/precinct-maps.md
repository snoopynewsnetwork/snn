# Ohio precinct maps — November 3, 2026 special Senate election

The election fills the unexpired U.S. Senate term ending January 3, 2029. **Research package complete with explicit access and geometry gaps; no November 2026 boundary approval or native-unit geographic crosswalk is established.** Open the [offline map index](maps/index.html) for actual downloads and usable previews for every priority county.

The package inventories all **88 counties**, retains one complete official Census 2020 Ohio VTD ZIP (**8,941 features**), and derives separate reference previews for the exact **32 priority counties**. County/municipal sources supply **20 counties with nonempty GIS geometry**, **205 complete PDFs / 466 pages**, and one historical precinct JPEG plus a verified official Tuscarawas GIS server-rendered PNG (raster only). The PDF count includes two ward/school supplements and one historical council map with precinct outlines; these are not counted as current precinct packages. Richland has no retained county precinct map download; browser viewability is not counted as a downloaded asset.

The exact priority order comes from [priority-set.json](data/turnout/priority-set.json): 4,581,738 / 5,704,620 all-seven-candidate 2024 Senate votes = **80.3162699707%**. The first 31 total 4,542,798; the top 15 total 3,525,320. All five separate volume measures select the same membership. The read-only county-turnout SHA-256 remains `d9133f7f88eca91b8bef8f3987b3e1abfb30b19e61d1d824a1e270dde4049a90`.

## Geometry, pagination and artifact validation

Every ArcGIS layer is queried for count and all object IDs, then complete batches of at most 50 IDs with all attributes, native spatial reference and `returnTrueCurves=true`. Count, unique ID set and returned batch identities must agree; transfer-limit flags fail acquisition. Countywide services used by a city app are retrieved without an app city filter. Medina WFS unbounded and high-limit results agree byte-for-byte with 203 hits; a 10-feature control confirms the limit behavior. Census original covers all 88 FIPS and is stored once.

Original ZIPs/components, native EsriJSON (including true curves and SR metadata), GML and PDFs/images are unchanged. Lossless gzip is explicit in metadata. Derived GeoJSON reprojects XY to CRS84 with full ring vertex counts and no simplification; native Z/M/curves remain in originals. Clark (2), Stark (9), Licking (2) and Greene (86) true-curve records use separately retained server-linearized rings for polygon-only derivatives. SVG previews fit native coordinates and round display positions only. The undated Mahoning ZIP lacks PRJ and is not reprojected.

Diagnostics test empty and invalid/self-intersecting geometry, nonfinite extents, all positive-area polygon overlaps, intersection errors and every attribute field’s blank/unique/reused values. Invalid source geometry is not repaired; no sliver cutoff silently removes overlap evidence. Some overlaps are tiny coordinate slivers or source split/overlay pieces; the full pair areas in native CRS squared units remain available for review. These checks cannot certify legal completeness or approval. PDF originals are checked for complete EOF and repair-free parsing; truncated historical captures are excluded. Each complete PDF has every page represented in a contact sheet, plus a larger first-page preview. Ashtabula’s actual JPEG format and original clipping defect are explicit.

[validation.json](maps/validation.json) and [artifact-manifest.json](maps/artifact-manifest.json) record the independent offline audit: hashes/ZIP CRCs, native counts and ID sets, all 17,811 historical unit identities, exact priority order/FIPS, geometry/vertex preservation, PDF manifests and local index links. Every individual retained file is below 40,000,000 bytes. See [REPRODUCE.md](maps/REPRODUCE.md) for rebuilding and auditing without refetching or modifying the original snapshot. Installed dependencies/caches are excluded.

No live collector, map approval, calibration, turnout model or precinct vote allocation is claimed.
