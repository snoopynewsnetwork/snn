# Kansas baseline schema and reproduction

Version `ks-baselines-v1`, research observed 2026-10-18 UTC. All paths below are relative to `data/baselines/` unless stated. Integers are source votes; fractional outputs are conditional expectations. Empty CSV numeric cells mean unavailable, never zero. CSV booleans are Python `True`/`False`. JSON missing values are `null`. Share fields use fractions in [0,1], except explicitly **unbounded** requirements; `_pp` fields use percentage points. Named contest votes, pair votes, ballots, registration and generic write-ins have different scopes.

The [report](../../../county-partisanship.md) is generated by [render_report.py](../render_report.py). The compatibility file [county-baselines.csv](../../county-baselines.csv) contains every one of the 105 Kansas counties. It is not a precinct crosswalk or a 2026 ballot mapping.

**Original evidence.** [references.json](references.json) records source IDs, requested/final URLs, response status/headers, retrieval UTC, hashes/sizes and read-only stored paths under the Kansas directory. The nine historical SOS XLSX/PDF originals are reused from `data/news/manifest.json` by exact decompressed SHA-256. Additional Census, turnout, certification and registration originals are reused read-only from `data/turnout/source/acquisition.json`. New bounded current primary captures are in [acquisition.json](acquisition.json). `.gz` always reconstructs the full original response-body bytes with gzip decompression; suffixes inherited from the newsroom capture do not change the actual XLSX/PDF MIME type. No original is truncated, simplified or rescaled. All stored objects must be strictly below 40,000,000 bytes. No large original is duplicated. Acquisition is optional for refreshing current sources; offline reproduction never fetches the network or changes shared evidence.

Source HTTP headers, including HTTP Date/Last-Modified, describe retrieval/publication clocks and are not inferred vote-update times. The original shared metadata did not retain a full redirect-history array; its exact requested/final URLs are retained and that limitation remains. New acquisitions retain every redirect. The current results-index capture supplies the official parent/download chain. State canvass PDF text is an extraction beside its hashed original, not a replacement for it. The complete original PDFs retain all unrelated offices without a second derivative for each.

**County identities and source scopes.** Five-character `county_fips` is Census STATEFP+COUNTYFP, `county_key` is `US-KS-`+FIPS, `county` is the official county spelling. The sole broad-result alias `Comanche `→`Comanche` retains the literal trailing space in native evidence. The 2022 turnout file's uppercase county labels are matched case-insensitively to the Census roster, including McPherson. Source spelling, native codes and leading zeros remain text. No cross-year, cross-family or November2026 geometry equivalence is asserted.

**County baseline columns.** In `data/county-baselines.csv`, each prefix `president_2024`, `senate_2022`, `senate_2020` has named candidate `<candidate>_votes`, `d_votes`, `r_votes`, `other_named_votes`, `named_votes`, `pair_votes`, `pair_participation=pair_votes/named_votes`, `d_pair_share=d_votes/pair_votes`, `d_minus_r_pair_margin_pp=100*(D-R)/pair`, `d_minus_r_named_margin_pp=100*(D-R)/named`, `d_minus_r_net_votes`, `historical_winner`, `margin_band`, and `pair_weight=county_pair/state_pair`. Bands use absolute pair margin ≤5 pp, >5–10 pp, >10 pp. `president_2024_rank`, `named_weight`, `cumulative_votes`, `priority_top15_or_min80` use **all four named tickets**, with descending integer total then ascending FIPS. County targets never omit the other 82 counties. Ballot/registration columns explicitly identify publication year and scope, and do not feed preference/scenario weights. `registration_2024_november_separate_publication` is the separate November registration workbook, not an imputed correction to the broad workbook. `generic_write_in_2020_published_supplement` is available for Shawnee/Sedgwick/Wyandotte only; other counties are blank, not zero.

The 2024 candidate keys are Harris, Trump, Kennedy and Oliver. Kennedy is Independent; Oliver is Libertarian. 2022 keys Holland/Moran/Graham identify D/R/L. 2020 Bollier/Marshall/Buckley identify D/R/L. Primary2026's 11 Democrats and 2 Republicans appear in candidate/native/control evidence, with party electorates separate; their sum is only an inventory of source activity, never a general-election electorate. No primary nominee or old native ID establishes the final current ballot.

**Raw/source position evidence.** [raw-rows.jsonl.gz](raw-rows.jsonl.gz) contains each OOXML row of the required contest workbooks, broad2024 turnout sheet and required turnout/registration controls, with `source_id`, exact `sheet`, `xml_path`, ordered original `row`, and column→decoded value `cells`. XML cells with no value remain null. Empty strings stay empty strings. Original OOXML bytes retain cell types, styles, formulas and all other source structure. Each original row is retained even if it has no requested candidate. [auxiliary-controls.csv](auxiliary-controls.csv) exposes the 2020 Sedgwick `Total Votes Cast` column, including 269 native detail cells and footer, and the adjacent 2020 Wyandotte presidential column without treating that candidate as Senate. Its categories explicitly identify these scopes. Four2020 Wyandotte footer candidate/write-in cells E131/F131/H131/I131 remain explicit `county_footer` observations in `native-candidates.csv.gz` and the original raw row. The current peer includes these cells; all121,053 detail candidate/total cells and96 footer positions reconcile without dropping either scope.

**Candidate observations.** `native-candidates.csv.gz` is losslessly compressed CSV with each required candidate cell, including generic write-in cells and county footers, never deduplicated. Unique source-cell key is `(source_id,sheet,source_row,vote_column)`. It records election date, stage, electorate, FIPS, `unit_key`, `role`, `native_components_json`, literal `source_candidate`, literal `source_party`, verified `canonical_candidate`, `candidate_name`, `party_identity`, `raw_value`, `votes`, `value_status`, and method. `published_integer` means an actual numeric source cell; `blank_unavailable` and `redacted_or_text_unavailable` are not integers. Header `NON` in Johnson2020 (also Shawnee source code) remains `NON`; verified candidate party comes independently from the main source and canvass. A write-in bucket is not a valid named candidate or a Democrat. `county_footer` rows overlap detail and never enter detail sums. `source/auxiliary-controls.csv`'s reported totals include generic write-ins where indicated, outside the named statewide certificate.

**Native units.** `native-units.jsonl.gz` has 22,031 historical source-native identities across five **overlapping alternative publication families**. A unit is grouped from literal candidate rows within one source, sheet and county. `unit_key` is `source|sheet|canonical_county|SHA256(compact UTF8 JSON native_components)`. `native_components` preserves ordered native fields: broad A:F district/location/county/precinct tuple; main sheets precinct and VTD with county separate; supplements every native code/name field, including unnamed Johnson2022 column D. VTD is only a source field, not a verified polygon. `rows` preserves all candidate `[row,column]` positions. `candidates` maps each named key to integer/null, plus generic write-in when published. `complete_named_values`, `known_named_votes`, `named_votes` keep complete totals distinct from known partial sums. `A_votes`, `B_votes`, `pair_votes` are general-election pair fields; primary values are null and `electorate_named_totals` separates party pools. Primary coverage's combined numeric sum is inventory only. Method is `not separately published` in these statewide workbooks; no central absentee/early board is invented from a place name.

The additional Sumner2022 original is independently parsed by `sumner_methods.py`. `source/sumner-2022-method-controls.csv` retains77 exact source cells for two ballot controls and nine Senate candidate/category rows across TOTAL plus six actual method headings. TOTAL is overlapping control; Not Assigned is a nested generic-write-in subtotal, not extra votes. Six method identities remain separate from the22,031 statewide-workbook identity contract. `sumner-method-targets.csv` has12 local/selected-only pair-target rows; all other state votes remain at the complete2022 county controls. No statewide method distribution, current method identity or geometry is inferred. Original source bytes/authority chain stay read-only in newsroom references. The primary source independently reports7,932 ballots versus the state turnout workbook's1,403; the discrepancy is not corrected or redistributed.

Main sheets cover101 counties; Johnson, Sedgwick, Shawnee, Wyandotte supplements are complementary. Within each supplement, the footer is overlapping control, not another unit. Broad2024 4,567 district intersection contexts and precinct2024 4,566 reporting identities are separate universes. The same name/count is insufficient to join them. `native-coverage.csv` inventories sheets/counties/units/zeros/unavailability and complete versus known totals. `native-county-reconciliation.csv` records each county/candidate known native sum, unavailable cell count, county control, residual and control basis. Residuals are comparison evidence only; no residual is distributed to missing units. Suppression affects 13 2024 precinct units,12 in2022,19 in2020,31 in2026 primary. Broad2024 is complete numeric evidence. All zero rows remain.

**Controls and priority.** `candidate-controls.csv` covers every named candidate in all three baselines and the 2026 primary, with distinct electorate/stage and primary statewide PDF control. `county-priority.csv` retains all105 ordered rows and exact cumulative integer counts; minimum80 uses `5*cumulative >= 4*denominator`, and the previous row fails. [build-summary.json](../build-summary.json) records the contract and source disagreements. Raw2022 ballot/registration inconsistencies remain source-scoped and are excluded from scenario weights. 2024 broad ballots1,343,020/registration2,031,120 differ from the certification release1,344,147/2,031,132. The November registration workbook sums2,031,132. These publications are not normalized together. Generic write-ins, valid named write-ins, undervotes, overvotes, blanks and method splits not reported by these statewide contest files remain unavailable. Ballots-minus-named-votes is an unclassified gap, not automatically undervotes.

**Historical scenarios.** [scenario-settings.json](../scenario-settings.json) is the executable/report contract: preference anchors are each general-election D/R pair, and low/base/high named-volume bases are2022/2024/2020. County pair pools use the chosen volume source's actual pair counts; its candidate-specific nonpair counts stay fixed. They are historical sensitivity anchors, not2026 projections or candidate effects. `state-scenarios.json` contains 22 runs:9 anchor×volume combinations×2 goals, plus2 pair-mix normalizations×2 goals. The normalized runs rescale every county and historical other count by the same stated factor to hold statewide pair volume at1,303,655. `county-targets.csv` has105 rows per run/goal,2,310 total. Pair and named weights both sum1; each row records its preference/volume/scale/participation, baseline/target shares, net contribution/gain, nominal and bounded +1share-pp gain, clipping, local pair tie/A+1 targets, and selected-only requirements. Every other county is held at its baseline anchor share plus the explicitly declared clipped `others_share_shift_pp` (default0), with the same weights. q<0 means already secured under those fixed assumptions; q>1 is impossible; zero pools are not divided.

At fixed pair weights, unbounded shift `(B-A)/(2*(A+B))` ties. An illustrative A+1 **pair margin** adds0.005 to A share. The bounded solver solves `sum(Tc*(2*clip(sc+delta)-1))=goal*sum(Tc)` by bisection, preserving both unbounded and feasible bounded shifts and the clipped-unit count. `net_gain_per_1pp_A_share=.02*Tc` is the nominal transferable gain; `bounded_net_gain_from_plus1pp_A_share` clips at1. Net votes, share points, margin points and all-candidate denominators/cushions remain separate. Plurality comparison retains each historical nonpair candidate individually; optional pair targets do not replace Kansas's legal highest-vote outcome.

`native-targets.csv.gz` contains every22,031 identity×2 targets,44,062 rows, including explicit primary-not-applicable, unavailable and zero-pool rows. Numeric historical native pairs have local pair tie/A+1 requirements and selected-unit-only state break-even with all other votes fixed at the whole-state county controls. Unknown selected cells remain unknown. The **complete broad2024** family additionally has a bounded native-uniform statewide solve and contributions, in `native-state-scenarios.json`. Partial precinct families cannot produce an exact fully identified bounded native-uniform statewide solve because of unavailable cells; the field is null and the gap explicit. County-based complete statewide solves remain available for every baseline. County-uniform and native-uniform clipped shifts are different scenarios. No suppression residual or old/new geography join is invented to force equality.

**Live calculator.** [live_remainder.py](../live_remainder.py) accepts JSON `counted:{A,B,other:{candidate:votes}}`, `remaining_units:[{key,remaining_contest_votes,other_shares:{candidate:fraction},A_pair_share}]`, optional `selected_unit`, `goal_pair_margin_pp`, `clip_shares`. All counted votes stay fixed. Each remaining pool is **contest votes**, not ballots: pair pool=`U*(1-sum(other_shares))`. Final pair denominator is countedA+countedB+remaining_pair; final all-candidate denominator is all counted candidates+all remaining contest votes. Unknown pools/preferences, negative/nonfinite pools, duplicate keys, invalid other shares and unapproved clipping return explicit statuses. Approved A-share clipping retains input/used shares. Selected requirements fix every other unit to supplied shares. Legal plurality boundary also compares each other candidate; strict win requires exceeding every final candidate. No-pool outcomes use fixed final counts. `synthetic-live-scenarios.json` contains15 input/output cases including unknown, no-pool win/tie/loss, negative, impossible/secured, both clipping directions, pair-win/other-loss and final denominators. These are arithmetic cases, not calibration or probabilities.

**Peer reconciliation and acceptance.** `reconcile_peer.py` only reads the actual peer's outputs. `peer-reconciliation.json` pins external peer asset hashes and every shared field/native/source-cell comparison. `peer-native-key-crosswalk.csv.gz` reconstructs the peer's exact SHA25624 contract from independently parsed raw native fields and headers. `native-order.csv.gz` ranks every fully numeric identity by descending named votes,FIPS,sheet,ordered source rows; unknown units remain in the full inventory but have no invented volume rank. All105 county order and minimum80 contract are exact. Coordinator acceptance files are external evidence, not rewritten or made to hash this package; there is no reverse hash cycle. Acceptance applies to historical research priority only, never November geography.

**Reproduce offline.** From repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -S senate/2026/kansas/data/baselines/reproduce.py
PYTHONDONTWRITEBYTECODE=1 python3 -S senate/2026/kansas/data/baselines/calculate.py --county Johnson --anchor president_2024 --volume president_2024 --target-margin-pp 0 --others-share-shift-pp 0
PYTHONDONTWRITEBYTECODE=1 python3 -S senate/2026/kansas/data/baselines/live_remainder.py path/to/input.json
```

Python3 standard library and Poppler `pdftotext` are sufficient. No pip packages, dependency/cache directories, Git operations or network calls are needed. `reproduce.py` runs extraction, targets, synthetic cases, peer comparison, report generation, validation and asset manifest. `validate.py` checks original/stored hashes, ZIP CRCs, candidate/county/native/source-cell balances, unavailable/zero distinctions, every scenario denominator/weight/contribution/selected requirement, bounded solves, meaningful live cases, exact80 crossing/order and local links. `validation.json` records actual checks and precise gaps. `asset-manifest.json` includes all owned assets plus the owned report/CSV, excluding itself to avoid self hashing. It includes a byte/hash reference to each shared original without copying it. Run it after final edits. Individual assets are strictly below40,000,000 bytes.

`acquire.py` refreshes only the explicitly listed current authority pages into owned capture paths. `recover_originals.py` verifies and reuses every present pinned original; only missing objects are fetched, with response metadata saved under `source/recovered/`. Changed responses remain source disagreements and never replace pinned/shared inputs automatically. Original request/final URLs and exact hashes in `source/references.json` make acquisition reproducible without relying on third-party candidate allocations.
