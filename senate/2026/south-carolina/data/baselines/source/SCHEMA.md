# SC partisanship source and calculation schema

Version: sc-partisanship-1. UTF-8; CSV empty fields mean unavailable/null, never imputedzero. Counts are integers unless explicitly scenario expectations. All gzip files are lossless: `gzip.decompress` reconstructs exact HTTPentity or CSV bytes. ZIPbodies retain exact original archives; `legacy-archive-members.json` records member names/bytes/SHA256 and validator checks CRC. All stored owned files must be strictly below40,000,000bytes.

`source/*.meta.json` pins requested/final URL, method, full response headers, redirect chain, UTC retrieval, original/stored size/SHA256, body_path and parent_source. POSTrequest.json stores exact transmitted bytes and request hash. Body paths are relative to the metadata directory and can reference immutable shared assets. History query bodies were independently re-extracted from actual official JS/fragments and compared byte-for-byte; see source-chain-audit.json. No query mutation is used. Existing news/source preparation stays read-only; shared-reference-evidence.json retains metadata/hashes and original scope, including failed retrievals with no body claim. shared-primary-references.json pins every reused VHM original and metadata hash.

The **database** tables `candidate-method-controls.csv.gz` retain all516586 rows in original scope/node/row order. Key=(contest_label,observation_scope,source_pointer); division_path is the original hierarchical DBID path. candidate_id+party_id+method_id keys are never deduplicated. raw_row_json contains every returned flag, percentage, adopted/adoptive value and vote. Scope candidate includes named candidates; generic_write_in is original ALL_OTHER_CANDIDATES; control:TOTAL_VOTES/TOTAL_BALLOTS/PSEUDOCANDIDATE are overlapping controls. TOTAL_VOTES is not another candidate. Complete metadata lists, including repeated method candidate keys/fusion fields, remain in candidate-universe.json and original JSON.

`native-units.csv.gz` has9823combined state/county/leaf rows. County FIPS joins use exact county names in original Censusnational_county2020.txt, documented in source/county-fips-crosswalk.json; DBIDs are not FIPS. Finer geography_key includes contest to prevent cross-year joins. raw_division preserves name/displayName/type/ID/all original division fields. source_observation_refs resolve through priority-set.json/source_observations to combined/method body/hash/UTC; source_pointer gives the exact location in both hierarchy views. State/county/precinct levels overlap and are never summed together. candidate_votes=A+B+other; generic_write_in is included where actually published. Pair participation=(A+B)/candidate_votes. Allcandidate and pair shares/margins/weights are separate. Blank/separate under/separate over/registration columns are empty when unavailable. Method ballot pseudo-options can disagree with combined controls and remain view-scoped.

`county-baselines.csv` is the top-level 46row wide county table sorted by2024seven-slate votes descending, FIPS as tie-break. Prefixes2024_pres/2020_senate/2022_senate/2022_governor identify electorates. c<ID>_p<PARTYID> columns retain each raw combined candidate/control. A=Harris/Harrison/Matthews/Cunningham; B=Trump/Graham/Scott/McMaster. BillBledsoe's databasepartyConservative differs from originalCON/ClerkConstitution; no relabeling. Current ballot evidence is separate, with filing IDs explicitly unaccepted as result IDs.

`registration-participation.csv.gz` retains7500relevant VHM rows from all46requested counties/year plus countyREG/VOT views, including summary and unassigned administrative rows. Source key=(source_id,source_pointer), not county/name. raw_identity_json preserves original nullable county/precinct/code/summary. CSVcounty is actual rowcounty when present, otherwise requested routecontext; this is not inferred physical membership. Codes are source administrative codes, not DBIDs/current precinct approval. total_participating is null forREG views; raw_total_voting preserves originalzero. Original complete demographics remain in bodies; no unrelated demographic derivative is created. VHM printed-list, BCM registration and ENRtotalVoters are separate scopes/releases.

The **original ENR** namespace is independent. legacy-source-positions.csv.gz retains every required XML/TXT element/line with original attributes/text. XML locators use ZERO-BASED ORDINAL AMONG ALL ELEMENT CHILDREN at each bracket, not ordinal among same-tag children. The root is /ElectionResult; e.g Contest[6]/Choice[1] means child6 is the Contest, child1 is the Choice (child0 may be aggregateVoteType). Validator resolves the full path against exact original XML and checks attributes/text. legacy-candidate-methods.csv.gz uses the same full-child convention, with separate choice_ordinal/method_ordinal/native_ordinal as presentation indexes. TXT locators identify1based line and exact0based UTF-8 byte offsets;30character ASCII fields are verified against literal headers. No synthetic XML is created for Clarendon. Original raw fixed-width lines/fields remain retained. JSON pointers are RFC6901style0based array pointers to exact combined P/V source positions; row ordinals are source-scoped, not invented official precinct IDs.

`legacy-native-baselines.csv.gz` contains9635combined original JSON rows; source P name, original candidate vector/analysis IDs, source contest key, source row/clock and exact-name companion turnout control remain distinct. XML/TXT methods are never used to allocate a combined residual. `legacy-candidate-universe.json` preserves full required summary objects, XMLchoice metadata/all-party labels, raw child ordinal and source order. Candidate analysis links use declared name tokens with a specific Hampton2024 typo alias; raw names/party never change. Charleston Provionsal is a declared comparison-only alias for Provisional. Missing Newberrywrite-inparty remains missing. legacy-election-controls.csv.gz preserves entire original election/native turnout attributes, even fields outside the requested contest. Unrelated offices are preserved in complete original archives/JSON but need no extra derivative.

legacy-reconciliation.json records all original source balances and unavailable disabledXMLattempts. legacy-database-comparison.json contains exact180methodcells/19matched contexts and both source locators/counts; legacy-native-identity-comparison.csv.gz covers every originalleaf. Native names are matched only exactly within a historical county/contest. 5442unmatched source spellings remain unmatched; no physical/geometric/cross-year/current join follows from names or equal vectors. Original state reportingcounts and candidate roster counts remain separate. legacy-native-priority.json gives original-source order independently of DBorder.

`priority-set.json` declares allseven-slate denominator, full descending46order, exact minimum80% via5*cumulative>=4*total, crossing and every historical native order. Tie-break is full sourcekey lexical after descendingvotes; every sourceID/body/hash/UTC/pointer is resolvable. Top15 union min80 is17counties;29others remain. coordinator_acceptance_path is path-only; this worker never writes coordinator acceptance. `peer-reconciliation.json` documents every compared field and exact schema conventions, including different human scope labels and VHM key formatting. No numeric disagreements are normalized away.

`sensitivity-settings.csv`: four historical preference anchors × six volume vectors. Four vectors are direct observed county pair/nonpair pools; low/high choose county minimum/maximum pairpool across four contests, carrying that selected source's nonpairpool. No scaling or2026projection is used. County base is2024pres. county-targets has2208rows (24settings×2targets×46counties); state-scenarios has48. All nonpriority counties remain. native-targets/legacy-native-targets have19270rows each (9635leaves×2targets); they use their own historical source preferences/pools, no cross-year native mix. legacy-method-baselines has57810source-native-method rows and legacy-method-targets115620rows, summing each complete original method vector to the same historical statewide pool. Raw DBmethod-baselines/method-local-targets remain separately flagged where incomplete.

Target columns distinguish pair_pool, other_pool, all_candidate_pool, pair participation/weight, baseline share/net/contribution, unbounded shift/share, bounded shift/share, clipping, targetnet/gain and selected-unit-only threshold/status. A+1 pair margin is1marginpoint, not1vote or1sharepoint. Unbounded delta=(g*T−M)/(2*T); bounded solver finds sum(w*(2*clip(s+delta)−1))=g*T. +1sharepp potential=.02w; clipped gain uses2w*(clip(s+.01)−s). Every other unit's fixed baseline net and zero shift are explicit in selected rows; q<0 secured/q>1 impossible/no positivepool remain distinct. all-candidate-cushions.csv targets1pp of pair+nonpair, not paironly. Synthetic impossible/unknown/negative/bounded cases are saved and tested.

`live.py` reads counted{A,B,others:{name:votes}} and remaining[{id,pair_pool,A_share,others:{name:votes}}]. Counted votes never change. Missing/None isunknown, negative/nonfiniteinvalid; shares outside[0,1] are explicitly clipped. Finalpair=countedA+B+remainingpair; finalall adds every counted/statedfuture named-other vote. Required uniform tie share=(U−L)/(2U); target adds targetnet from FINAL pair or all denominator. Selected-only holds all other remaining shares at individually listed clipped assumptions. Strictplurality requires A above each named opponent; equality is not a win; boundary>=1 is impossible for strictwin. Generic write-ins are not a factual named rival. Unknown/no-pool/secured/impossible cases are explicit, probabilities remain null. Thirteen meaningful fixtures, including an all46synthetic illustration, are stored as arithmetic evidence only.

Offline sequence is reproduce.py. Acquisition scripts are opt-in and never overwrite an existing capture; capture a newsourceID for a newrelease. Pythonstandardlibrary suffices offline; requests is needed only for acquisition and Poppler only for regenerating visual PDFpreviews. No dependency/cache directories are retained. validate.py independently resolves rawsource/XML/TXT locators, checks hashes/CRC/identities/coverage/allcandidate balances/denominators/exact80, uses an event-slope boundedsweep as an independent solver check, checks live edge cases and all relative reportlinks. asset-manifest.json lists all owned assets with hashes/bytes except itself to avoid self-hashing; its validation.json entry is deterministic. Shared originals are separately pinned and verified. No future current-geography approval, live collector, cadence or calibrated probability is claimed.
