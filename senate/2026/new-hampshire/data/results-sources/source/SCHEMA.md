# Official-source evidence schema

All paths in this document are relative to `data/results-sources/`, except explicit state-relative references. Only `official-results.md`, `data/official-results-sources.csv` and this evidence directory are owned by this assignment. Peer/coordinator files are read-only. Synthetic historical keys are never current state-issued numeric IDs, authority approval or legal geometry.

`source/*.json` with `body_path` is one immutable HTTP observation. It records source ID, parent source token, exact requested and final URL, UTC request start/end, status, curl exit/error, completeness, original entity bytes/hash, locally stored gzip bytes/hash, full-header hash and curl metadata. `source/*.headers.txt` retains every response-header block including redirects; the final HTTP block and curl effective URL govern the response. Last-Modified, Date, Memento/capture, election header, document-created and retrieval clocks have distinct meanings. A parent token may identify a captured parent, bounded discovery job or indexed-primary observation; an unresolved token is not a fabricated downloaded parent. External original-reference metadata retains its original HTTP representation, including inherited shared-source provenance.

`*.body.gz` is exactly one deterministic local gzip of the bytes curl saved. Curl requests `Accept-Encoding: identity` and does not silently decode HTTP content encoding. If a server nevertheless sends gzip, the original entity can itself begin with gzip magic; `inspect_html.decode_body` explicitly decompresses that second layer for text inspection. Hash verification of an owned original uses only the outer local layer; the second layer is not mistaken for the original entity. Failed/partial/403/404 bodies remain complete access observations with their status and completeness flags, never election data. No payload is truncated. Every stored object is strictly below 40,000,000 bytes. The current owned corpus needs no original-byte reconstruction split. Large peer originals are reused by exact hash rather than duplicated.

`source/history-original-references.json` covers all 23 source rosters. `source/control-original-references.json` covers the independent House Clerk, FEC and NARA originals. `source/current-ballot-references.json` pins the exact Farmington image-only general sample and primary parent metadata. Their paths are state-relative, with stored and original hashes/bytes and HTTP metadata paths; decompression/storage follows the referenced owner's metadata. The owned manifest also inventories read-only dependencies and these source chains. No maps manifest/report is pinned. The final first-wave reports/manifests were explicitly frozen before pinning; the coordinator acceptance is external authority, never hashed back into the contract.

`historical-rosters.json` lists 23 separate, complete 320-row source-native rosters (7,360 records), each with a gzip JSONL native file and full-original positions file. Full original BIFF worksheets retain sheet/index, one-based row, ordered values and every cell type. BIFF types are xlrd codes: 0 empty,1 text,2 number,3 date,4 boolean,5 error,6 blank. OOXML rows retain one-based row, original cell address/attributes/type, raw cached value, formula and parsed value. PDF extraction retains every page and line in Poppler layout order. These positions are source locators, not precinct or candidate IDs. Numeric source IDs unavailable in the original remain JSON null; none is autofilled.

`historical-native-records.jsonl.gz` holds all 7,360 records. Source ID + zero-based roster position identifies one original source-scoped row. County and literal native label, full original position, source locator, raw fields, cell types, original header and mapped fields remain separate. Mapping uses the header nearest the source row (including the reversed 2022 SUMMARY candidate order) and the published A/G block in the 2020 side-by-side ballots sheet. Original labels, trailing spaces, dashes, correction asterisks and blank cells are retained. Parsed `fields` are nonnegative whole counts or null; null is not zero. Administrative regular/absentee/ballots/checklist/new-registration fields never become candidate votes or assumed current geometry. Candidate field names are analytical schema labels, not source-issued candidate IDs.

`historical-audit.json` preserves independent numeric sums, all 483 original county/state controls, their raw fields/positions and signed differences. Available numeric cells are summed explicitly; missing/blank values are not imputed. County summaries/footers and municipal controls overlap leaves and never add votes. Historical vintages coexist, with unknown release chronology and literal disagreements. The sole ranking denominator is the linked 2024 `_3` four-ticket plus generic Write-Ins subtotal826189; under/over, ballots and registration remain different scopes. Exact integer prefix crossing/order is independently checked. `history-validation.json` summarizes those checks.

`data/official-results-sources.csv` (one level above this directory) has321rows: one state-authority row and320native historical leaves in full frozen descending order. `source_geography_key` is the exact frozen source key. `priority` is lowercase boolean text, `priority_rank` is integer text for143selected rows and blank otherwise; `full_historical_rank` remains1–320. County FIPS is an identifier string. Native labels and explicit parent labels preserve the contract. `ward` is source-explicit integer text or blank. JSON-valued columns preserve raw fields, locators, all exact literal source-roster references and actual published ward/directory links. Current numeric/election/contest IDs, cadence and exact-remaining cells are blank; candidate-ID JSON is literal `null`. The state row is an authority record, not a current numeric source ID. No zero fills a missing numeric field.

`native-source-inventory.json` mirrors the320leaf CSV rows. `priority-investigations.json` has143separate records in exactly the frozen order, each carrying its raw basis record, source locator, literal cross-roster references and full shared parent review. `municipal-inspections.json/.md` has98shared parent investigations, with selected current primary channel, exact HTTP outcomes, archive distinction, actual published result/general/ward links and character positions, document status, polling/correction snippets and qualified findings. One office can support several ward investigations. A municipal channel is not necessarily an independently proven historical ward clerk or current reporting-unit equivalent. Remaining177leaves retain discovery scope; territorial/delegated authority is unknown until evidenced.

Literal cross-roster navigation joins only exact county + trimmed literal native label, never fuzzy name similarity or ordinal position. 289basis leaves have23literal references;31have fewer because of alternate labels/asterisks/abbreviations. This does not delete any source row: every source has its original320. The join does not establish boundary stability across years or equivalence to November2026. Contract numeric IDs and geographic status are never upgraded by these references.

`derived/<source-id>.json` from HTML includes original/base URLs, literal HTML BASE, resolver version, visible text, and every anchor's literal href/text/character offset/resolved URL. Archive-relative links are resolved against the original embedded URL; normal links obey the document BASE. `resolution-corrections.json` records version1 resolver mistakes and actual version2 destinations; old failed requests stay retained. Northwood's corrected actual links succeed; those former wrong requests are not alleged municipal access failures. `repair_resolution.py` is historical online-discovery replay, not part of offline reproduction.

`document-extraction.json` distinguishes complete PDF text extraction from image-only/unextractable text. PDF text gzip and full page/line JSONL are secondary views; originals govern. `sample-audits.json` tests exact local panel arithmetic/source scope for Portsmouth,Londonderry,Salem. Salem's2026primary polling sites are not November IDs or new leaves. Scanned/manual is not assumed election-day/absentee. Generic tally and write-in adjudication reports overlap. Rendered `qa/*.png` are visual evidence, not substituted originals. The Farmington Senate transcription in `current-ballot-review.json` was independently visually read from the exact image-only general original; result IDs remain unavailable.

`independent-controls.json` retains full selected House/NH panels and FEC NH positions plus counts and disagreements. Repeated House recap, NARA elector slates and multi-page FEC column groups are never added as independent ballots. NARA visual scope is only the independently viewed certificate panel. `poll-hours-evidence.json` retains explicitly current general notices and local/UTC conversions, not a complete statewide poll-hours list. `rule-evidence.json` preserves exact statute section text/offsets and narrow court-order scopes; the Supreme Court snapshot is not a guarantee of future docket status. `state-inspection.json` distinguishes official authority from unverified public-feed schema/status.

`peer-final-verification.json` checks the user-supplied final first-wave report,CSV,manifest,contract pins, all native fields/types/controls and ranked order read-only. It documents the sole schema aliases (ballots_cast/ballots_total and equivalent A/G locator notation). The older reciprocal witness has its own version; no earlier label hash is presented as the final baseline CSV. Maps evidence is informational/current-source reference and stays outside this freeze's dependencies.

## Reproduce offline

Requirements: Python3.10+, xlrd2.0.2, Poppler `pdftotext`/`pdftoppm`, standard IANA timezone data. No dependency/cache directories are stored here. The extraction script also recognizes the existing external `/tmp/snn-xls-reading-libs` location; alternatively put xlrd on Python's ordinary import path. The original spreadsheets are read only; no Excel save/recalculation changes cached values.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 senate/2026/new-hampshire/data/results-sources/reproduce.py
```

This sequentially extracts originals and positions, compares peers, validates federal/local controls, renders visual previews, builds current observations/inventory/report, performs meaningful offline QA, and builds/verifies the complete manifest. Network calls and discovery reruns are excluded. Visual transcriptions are retained reviewed observations; reproduction renders their exact originals, not an automated claim of new visual review. Deterministic gzip usesmtime0. No script invokes Git or writes another assignment.

## Re-request observed originals

```sh
PYTHONDONTWRITEBYTECODE=1 python3 senate/2026/new-hampshire/data/results-sources/acquire_all.py --output /tmp/nh-official-new-snapshot --only court-scotus-docket
```

Omit `--only` to replay every owned observed request. A new empty destination is required. Response mutability, current failures and clocks may differ; a new request is never used to overwrite or claim reproduction of a historical snapshot's exact bytes. `acquire.py SOURCE_ID EXACT_OBSERVED_URL [PARENT_ID]` is the individual acquisition primitive; discoveries use actual published hrefs or explicitly indexed primary URLs, not guessed feed endpoints. Bounded archive queries/captures are retained separately. The historical23originals remain reusable through exact read-only references; network reacquisition of them is not needed for offline validation.

`validation.json` is deterministic and includes coverage/order/identity tests, candidate balances and administrative differences, first-wave checks, raw and stored hashes, current-ID null checks, relative links, file bounds and cache exclusions. `asset-manifest.json` hashes every owned file including validation, excluding only itself to avoid recursive self-hashing; final manifest integrity is checked separately and reported at handoff. No reverse contract hash is introduced.
