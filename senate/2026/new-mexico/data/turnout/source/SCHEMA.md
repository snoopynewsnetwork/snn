# New Mexico turnout schema and reproduction

This package is an original-source research extraction, not an accepted current geographic crosswalk or live collector. Its report is `../../../turnout.md`; `../../county-turnout.csv` is a compatibility filename containing **native source rows**, not an authorization to replace them with counties.

Run `PYTHONDONTWRITEBYTECODE=1 python3 senate/2026/new-mexico/data/turnout/run_offline.py` from the checkout root. Standard-library Python and Poppler `pdftotext` are required. No network, coordinator derivative, peer derivative or dependency directory is used during replay. `acquire.py` reuses verified original assets/receipts and follows literal public links for uncached observations. Public HTTP requests require network access; no guessed current contest IDs are requested. `common.py` records each redirect entity, final original entity, status, request/response headers, URLs, UTC retrieval, raw/stored hashes/bytes, gzip and parent/discovery basis. Earlier shared receipts retain their original metadata format; their exact bodies are referenced read-only by hash.

## Geography and arithmetic

Native keys are literal `nm:elstats:<contestID>:<county label>:<native label>`. Source labels and source position are retained; no numeric division ID is manufactured. Legacy keys include the election year, local county ID and exact turnout label. Registration-stock identities use source ID/page/line plus label and continuations, not an invented precinct-number crosswalk. All source keys are unique within their universes.

`Voter Privacy` rows are administrative aggregates under the source county, not polygons, early voting sites, absentee boards or independent physical precincts. Their source totals may combine suppressed selections. The package does not reconstruct protected values or allocate any residual. Unknown membership remains unknown even if a county residual is zero or a printed total appears to imply a value.

State calculations use 33 disjoint county candidate controls per contest; native candidate sums are separately reconciled as observed numeric sums plus unallocated gaps. Methods partition a particular candidate or ballot universe, not extra votes. Portal ballots, PDF ballot versions, reported contest totals, registration stocks and candidate votes are independently scoped; no averaging/rescaling. Every nonpriority unit remains in the arithmetic and inventories. Historical names/counts do not approve current boundaries or 2026 mappings.

Integer threshold: sort largest first, accumulate, take first `k` with `5*cumulative >= 4*denominator`. Require `5*preceding < 4*denominator`. This proves minimum cardinality only in the explicitly known universe being sorted. Source-row tie breaking gives a deterministic selected set; alternatives at equal vote counts may have the same minimum cardinality. Exact top15 numerator/denominator are retained; display percentages are calculated last.
