# Florida official-results evidence schema

All paths in JSON/CSV receipts are relative to `senate/2026/florida` unless a source document explicitly supplies another base. A source ID is a local evidence label, never an election identifier.

`source-ledger.json` contains every complete own HTTP observation, including errors. `shared-evidence.json` pins full existing individual source receipts and the three complete historical ZIP originals. Reused bodies are accepted only after exact decompressed SHA-256 and byte equality; another worker's extract is never an independent original. The exact requested/form/final URLs, request method/body, headers, redirects, HTTP status, UTC fetch interval, transport encoding, raw/stored bytes and hashes survive. Original Content-Encoding is decoded by requests; `gzip.decompress` restores the complete decoded HTTP entity, not wire framing. A publisher clock is interpreted separately from HTTP Date/Last-Modified and retrieval UTC. Null timezone stays null. A numeric stampedtime token used only for equality by client code is opaque.

`frozen-context.json.gz` is a **complete semantic copy of the frozen derivative contract**, including all source, count, order, administrative and unavailable objects. Its external acceptance remains PATH-only; the worker flag stays false. `county-investigations.jsonl.gz` has 67 ordered parents; every record contains its full frozen parent and primary constituent object, plus **all four historical native contexts as full objects**, each with its original global position. Sorting those positions reconstructs all 23,532 native objects exactly. No name/ID projection replaces them. This derivative retention does not duplicate any raw historical ZIP.

The historical original19 fields retain string values, whitespace, null/blank distinctions, source member, one-based row, byte offset, line bytes/hash and native identity. In observed positional order they cover county code/name; election number/date/name; precinct identifier/polling label; four repeated registration observations; contest name/district/code; candidate label/party; FVRS/DOE candidate identifiers; votes. There is **no separate method column**. IDs `900/901/902` denote generic write-in marks/overvotes/undervotes in the documented source scope. Registration repeats per candidate; it is not additive. Source-native polling labels, including central/early/mail hints and blank identifiers, remain unchanged. The [original source schema](https://fldoswebumbracoprod.blob.core.windows.net/media/709209/final-precinct-level-elections-data-definitions-and-field-codes_20250624.pdf) is retained by exact shared original reference. EAVS participation methods and bookclosing registration remain separate administrative snapshots with their own dates, missing/sentinel values and definitions.

`extracts/vr-complete-tables.json.gz` preserves every contest table, row/cell position, HTML/attributes/native text, all input/select controls, full header context, clock and election heading from 47 complete public VR result HTML entities. A dash is unavailable, not zero. The public HTML specifically describes suppression of small method groups. A named candidate total can therefore be present while details cannot reconcile numerically. These local method categories are not assignments to the original19 native units.

The state ElectionWatch pipe files are separate **August 18 primary** originals. `r` rows identify contest and election type; `c` rows identify candidates; `p` rows specify contest/county precinct counts; `u` rows identify county units; `V` rows contain status, race/unit/choice keys, reporting counts and cumulative candidate votes. Full raw rows, ordering, byte positions and sequence values survive. The companion `.xls` is actually the same tab-delimited entity as `.txt`, verified by hash. It is not a binary workbook. The pipe and TSV formats disagree in saved fields, and the pipe status is `I` even where the selected HTML shell says Official. They are not assumed synchronized or interchangeable. `SEQNO` is a record sequence, not an observed publication interval.

`extracts/broward-complete-xml.json.gz` retains the full XML root controls and ordered `Table` fields, null text, tags and attributes. `ElectionID`, `RaceID` and `ContestantID` are scoped to that county/election. `GeneratedDate` includes an offset. ED, early, mail, provisional and OTHER counts, generic write-in, withdrawal and winner flags survive; a flag or republished clock does not create a November election or legal certification.

`extracts/pinellas-complete-json.json.gz` retains every original JSON object/array and precision. Version `355096` belongs to historical election `122583`; Senate `K="0004"` is not a current ID. Summary `CH/P/V` arrays align by source position. Detail `P/V` arrays have 286 units, six **literal protected cells per unit**, `T=null`, empty `Eid/Cid`. No numeric detail total can be computed. Summary `BC=TV=0` are not independently validated zero-ballot counts. Settings publish an explicit EST clock. `IsCumulative=null` is not an incremental-feed instruction.

`extracts/lake-complete-csv.json.gz` retains every CSV record and all columns in source order. Current setup election `4079` has Senate DOM route `61160`, three named choices, 92 precinct labels and 276 candidate/unit rows. CSV choices have names/parties but no candidate identifiers. All candidate votes are zero and the parent says not reported/pre-election. It is a schema/setup sample, not genuine returns or approved geography. Native CSV order is deliberately not sorted.

`extracts/polk-complete-csv.json.gz` retains all 82 summary and 9,249 precinct CSV records from the actual linked historical reports, including original columns, source order, blanks and method dashes. The 1,032 Senate candidate-unit rows cover 172 labels and reconcile to the summary, including 383 generic write-in marks. The five printed candidates match DOS; the linked HTML's five-candidate subtotal is 431 lower. Both observations survive without an inferred correction time, cause or outstanding-ballot count.

PDF text extracts retain complete page order, with the original PDF hash in the receipt. Text is a derivative, not a replacement for the PDF; visual previews are separate. PDF table column order matters: Lee 2022 `VC/VBM` is not silently relabeled ED/EV/mail. Candidate database `Won` values are in the **primary** column; all-status filing records are not November returns. `current-candidate-all-status.json` preserves full tables, controls and source rows, including DNQ/withdrawn records.

`validation.json` reports substantive raw-original, geography, native, method, candidate, missing-value and arithmetic checks. `asset-manifest.json` lists the **exact owned path set**, bytes and SHA-256, excluding only itself. No source/error entities are truncated or simplified, no raw originals are duplicated, and every stored file is strictly below 40,000,000 bytes.
