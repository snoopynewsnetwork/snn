# New Jersey original-first turnout schema

This package owns only `turnout.md`, `data/county-turnout.csv`, and `data/turnout/**` under the NJ state directory. Python scripts resolve output paths from their own location. Acquisition requires requests/network access; offline PDF text uses Poppler; bounding-box native extraction uses PyMuPDF. Do not execute shared preparation scripts in place: their default writers are outside this assignment.

## Primary layer and keys

`extract/native-rows.json` holds four independent source scopes: 2024 Senate, 2020 Senate, 2018 Senate, 2024 president. Every raw municipal/admin candidate row retains exact source ID, 1-based PDF page and 1-based `pdftotext -layout` line, literal row text and candidate column vector. Municipal footers and statewide candidate controls are separate, nonadditive records. The full original and layout-text bytes are retained, including all fields outside extracted questions.

Canonical ranking key: `<source-id>:p<page padded4>:l<line padded4>`. It is a positional evidence key, not an election-office geographic identifier. Canonical ties sort descending integer reported candidate sum, then this full key lexically. No current/geographic normalization occurs. Native punctuation, source misspellings, party/ballot labels and administrative names remain literal. County FIPS are standardized five-character parent codes assigned to the explicit named county, not source-native municipality IDs. Municipal FIPS/geometry/native2026 IDs remain unavailable. County parents and their totals are never added to their children.

2024 Senate has 575 disjoint rows: 564 municipal-labelled rows and 11 administrative rows (ten Federal/Overseas variants plus Atlantic Hand Counts). Its candidate column order is Kim, Bashaw, Khalil, Kaplan, Mooneyham, Kuniansky. The ranking sum includes only these six published numeric columns. The statewide/municipal original supplies no write-in column. Literal blanks in Cape May Federal Oversees candidate columns remain null; independent numeric sums reconcile every published candidate/county total. Do not replace blank cells with zero. Source `(w)` and `*` flags are literal flags, not write-in classifications.

2020 Senate order: Booker, Mehta, Burke, Fernandez, Hoffman. 2018 Senate order: Menendez, Hugin, Flanagan, Hoffman, Kimple, Rivera, Sabrin, Schroeder. 2024 president order: Harris, Trump, Stein, Kennedy, Oliver, de la Cruz, Terry, Kishore, Fruit. The statewide candidate PDF order can differ; matching is by verified literal candidate name within that source/year, preserving raw header text, party/slogan and page. These are independent contest/year universes, with no inferred geographic crosswalk.

`data/county-turnout.csv` is a compatibility filename. Its 575 rows are the municipal/admin primary layer, with integer candidate votes, contest sum, denominator, cumulative count, top15/minimum80 flags and exact source positions. Blank optional fields mean source-unavailable or not safely linked, never zero. Ballot fields link only exact same-county/same-vintage literal labels; nonexact aliases are not silently joined. All available unlinked ballot records remain in `extract/ballot-rows.json` and their own statewide arithmetic. The 144 exact-label link gaps do not mean the municipal ballot publication is missing those records.

## Ballots and registration

Monmouth 2024 separately publishes Election Day and Early Voting provisional ballots; those fields remain separate. The source's generic provisional field stays null there. Administrative registration can be null or an explicit published zero; the distinction survives. Missing ballot percentage is not derived from registration.

`extract/turnout-controls.json` retains all21 county rows plus the state footer for 2024, amended2020 and amended2022. It separately retains rejected ballots and election-district counts. Ballots, rejected ballots, candidate votes, source blank ballot fields, undervotes and overvotes are separate concepts. The 2024 ballots-minus-six-candidate-votes gap is not labelled an undervote/overvote count. Registration is the source's reported election stock; active/inactive definition and exact snapshot date are not established by these tables.

`all-source-orders.json` and `sensitivity.json` independently rank every candidate scope and each ballot/registration scope. Registration ordering excludes explicit null-stock administrative records and lists their keys; published zero records remain. Every other geography stays in its measure's denominator. No cross-year joins or forecast weights are inferred. `county-controls.csv` is a nonadditive comparison layer.

Acquisition failures/empty current responses are precise bounded limits, not claims of nonpublication. `priority-set.json` enumerates all primary rows, full order/priority/remainder and every available finer/source-page reference, including unavailable/suppressed/administrative cases. Finer layers never replace or add to the575 disjoint state-publication objects.

Early Voting/Election Day/Mail-In/Provisional overlap their `Total`; municipal summaries overlap their districts/central units. All source positions remain, with no source-row deduplication.

* Salem: `extract/salem-required-native-dom.json.gz` retains43 Senate and43 presidential district tables, source DOM IDs, district/contest/candidate keys, character offsets and literal candidate names/votes. Accessible duplicate spans are presentation duplicates; each table candidate row is read once. Named write-in strings, zero counts and legal eligibility are distinct. Official PDF SOV and scanned summary bytes are also retained; scanned text absence is not a zero result.
* Atlantic, Morris, Sussex, Union and Salem PDF pages: `extract/county-required-literal-pages.json.gz` retains all relevant page text with every nonblank source line and position, including source headings, methods, totals, registration/ballot fields, protection and footers. `county-native-header-index.json.gz` indexes recognized native headers/rows, without deduplicating repeats. Original full PDFs and full layout text remain definitive for headers not safely parsed. `native-pdf-senate-total-rows.json` is explicitly a partial specialized extraction of Morris/Sussex/Union numeric TOTALs; wrapped/protected layouts leave coverage gaps. Its incomplete sums are parser coverage limits, not asserted source discrepancies or allocations. `native-audit.json` exposes these limits and raw source positions.

County write-in summaries and named strings are retained in their own source universes. There is no verified all-state generic/named/legally eligible write-in tally. Native administrative labels, polling sites, vote centers, election districts, split styles, VTDs and current precinct polygons are not treated as equivalent. No2026 legal boundary/feed crosswalk is supplied.

## Provenance and storage

Each `source/*.receipt.json` records exact requested/final URL, UTC retrieval, status, headers, redirects, parent discovery source, decoded entity-body raw SHA256/bytes, deterministic gzip stored SHA256/bytes and original body path. Requests `.content` represents decoded HTTP entity bytes; PDF/XLSX originals are otherwise unchanged. Every stored object is strictly below40000000bytes. Errors without a response have a literal client error and no invented HTTP status/body. Initial sandbox DNS failures are retained separately as `network-restricted` receipts. Protocol-relative directory links initially produced client MissingSchema errors; explicit HTTPS recovery receipts preserve the actual successful/failing request. These are client failures, not claimed remote HTTP responses.

Shared original receipts are individually frozen under `source/shared-*.receipt.json`; their `reference_path` is relative to the receipt directory, and both raw and stored hashes are checked. They refer read-only to original `data/news` assets, never an appendable aggregate as the continuing authority. Acquisitions never overwrite an existing receipt. `clerk-2020-reference.json` likewise uses source-directory-relative reference paths and identifies inherited evidence; this worker independently extracts the primary section without claiming a new retrieval. The read-only news manifest/preflight/reports/README/strategies remain untouched. Third-party catalogues are discovery only; no derivative allocations are used.

`asset-manifest.json` inventories all owned files except itself (self-hashing is impossible), with exact relative state path, SHA256 and byte count, including individual originals and frozen witnesses. Original shared assets are separately pinned by their source receipts; no huge original is duplicated. `pre-peer-witness.json` lists exact original pins and individual gzip copies of authored/extracted bodies before any peer derivative read. A subsequent change must leave that immutable version intact and create a separately named continuation witness. Bounded reciprocal review of the actual peer's captured completed original-first core is now complete in both directions. Coordinator acceptance remains false.
