# Virginia partisanship evidence and calculation schema

All paths are relative to this package unless explicitly state-relative. `county-` filenames include all 95 counties and 38 independent cities. They never mean county-only coverage. Source values, scenario assumptions and legal/current identity claims are separate.

`input-pins.json` freezes 166 original source receipts and complete response entities before any turnout derivative access. Each state-relative entity path has stored SHA256/bytes and decompressed SHA256/bytes. Whole receipts include requested/final URLs, parent constructors, hop bodies, response headers/status, request headers and UTC clocks. `additional-pins.json` pins the subsequently acquired official final-election roster workbook. `legacy-provenance.json` retains the earlier blocked directory/source-document observations and full original receipt records. Shared originals remain read-only, referenced by exact hash; no mutable peer helper or directory glob is a build input. `acquire.py` accepts an explicit key/URL/parent, records complete redirect entities, and refuses overwrite. Fresh public GETs request identity encoding. The entities are HTTP response bodies after transfer framing, not unavailable TLS packet/wire captures. Old newsroom receipts do not retain intermediate redirect bodies/request headers; that historical limitation remains explicit. Source clocks/status are literal, distinct from UTC retrieval clocks.

Every stored file must be strictly smaller than 40,000,000 bytes. Gzip files are lossless complete streams, mtime0 for our derivatives. Shared change-log raw entity is 77,397,161 bytes, stored whole as gzip below the limit; it is never truncated. It is retained for source evidence, not implemented as a chronological revision replay. Original unrelated office/statistical fields survive in these entities without an unnecessary unrelated-office derivative. No dependency or cache directory is retained.

`extracted/*-senate.json.gz` and `2024-president.json.gz` contain both source header rows, candidate column positions, party literals, every original CSV record/cell token/physical line range, hierarchical source rows and controls. `source_key` is our literal `YEAR-office:record:N`, where N is the numeric, one-based logical CSV record including both header rows. State, Locality and Precinct levels overlap; only Precinct records form the native accounting partition. Parent stays explicit, including provisional/central/administrative names. No crossyear native match is attempted. `record`, `line_start` and `line_end` refer to complete decompressed originals; original byte positions are reconstructible from the physical lines without dropping any bytes. Input bytes preserve quotes, delimiters, line endings and empty records beyond parsed tokens. UTF8-sig is used for historical CSV; the full official bulk export uses cp1252. The original encoding failure and blank-record checker repairs survive under `history/`.

Full HTML `__NEXT_DATA__` objects are saved under `extracted/*-hydration.json.gz`, preserving complete candidates, pseudocandidates, parties, `nVotes`, alternative `nVotesParty1`, control fields, notes, verification clocks and source links. Pseudocandidate Total Votes Cast is a control, never an additional candidate. Generic Write-Ins are not a named eligible allocation. Unbounded common A-share shift is `(target_pair_margin*T - baseline_net)/(2*T)`; for tie this equals `(B-A)/(2*(A+B))`. A+1 pair margin adds0.005 share, or0.5 share percentage points. A +1 share pp gain supplies0.02×pair_volume net votes. Bounded common shifts solve `sum(Tu*(2*clip(qu+delta,0,1)-1))=g*T` and may differ. Every unit contribution, pair/all weight, participation, gain and selected-only raw threshold/status survives. For selected u, all others stay at their explicit unshifted source/scenario shares and volumes. Raw required shares below0/above1 are secured/impossible, never feasible after relabeling. Zero-pair shares remain undefined.

These are conditional historical volume/mix tests, not researched2026 projections, inferred candidate effects or a native crossyear join. All nonpriority parents remain.

## Offline calculator JSON contract

Invoke `python3 -B data/baselines/calculator.py input.json`, or pipe one strict JSON object to stdin. Output is one strict JSON object. Expected invalid input returns status `invalid-input`, exit2 and empty stderr; successful arithmetic exits0. Duplicate JSON object fields and NaN/Infinity tokens are rejected. No probability or legal declaration is returned.

Required root fields: `mode` (`historical` or `live`); `pair` (two distinct nonblank exact candidate strings); `other_candidates` (distinct nonblank strings with no pair collision); `candidate_universe` (`supplied` or `full`); `unallocated_generic` (boolean); nonblank `assumptions`; `target_pair_margin` (finite numeric fractional units in[-1,1], bool/null/text rejected); nonempty `units`. Optional `selected_unit` must name an exact existing key. No string/number coercion. Keys are globally unique nonblank strings; whitespace tests blankness but does not trim/alias identities. All keys and all volumes/shapes are validated before unknown/no-pool/selected early returns.

Each unit has exact `key`, `pair_participation` in[0,1], `share` in[0,1] or explicit null for unknown pair preference, and `other_allocations`, a complete object of within-other fractions for every other candidate. Allocations sum to one (tolerance1e-12); positive nonpair pools require a supplied identity allocation. An empty other list is allowed only with no nonpair volume. At zero other pool, historical build placeholders are mathematically unused, not inferred preference. Historical units use finite nonnegative `volume` = all-candidate reported-vote scenario volume. Live units use finite nonnegative `remaining` = only uncounted all-candidate vote pool, plus `counted` for every supplied candidate and `counted_all_candidate_total` exactly equal to its sum. These volumes are candidate votes, not an inferred ballot or eligible remaining universe. No unsupported runoff/RCV mode is accepted; stages/electorates must be separate inputs if researched elsewhere. All individual and aggregate/derived values must be finite; negative counts, overflow and smaller/unbalanced all-candidate totals are invalid before arithmetic.

Live arithmetic: counted candidates remain fixed. Remaining pair votes=`remaining*pair_participation`; remaining A=`pair*share`; B=`pair*(1-share)`; other=`remaining*(1-participation)*allocation`. FINAL pair denominator=counted A+B + all remaining pair. FINAL all-candidate denominator=all counted + all stated remaining. Target pair net=`g*FINAL_pair`; its all-candidate margin is separately target net/FINAL_all. With counted lead L and remaining pair U, required common remaining A share=`(U+g*FINAL_pair-L)/(2U)`. Selected-only uses fixed counted lead plus every other unit's supplied remainder preference. It can solve an unknown selected share only if every other positive pool has a known preference. Unknown positive other preferences remain unknown; zero-pair preferences stay undefined. No-positive-pool and fixed-target statuses are separate. Negative raw shares stay secured, >1 impossible. Unbounded additive share algebra remains separate from feasible clipped common shifts and per-unit target contributions. Baseline projected full candidate plurality is evaluated across the supplied field, with `supplied-universe-only` whenever incomplete or generic allocation unresolved. A pair leader can lose to another named candidate. `legal_declaration` is always false.

`scenarios/fixtures/` retains meaningful actual CLI inputs/stdout/exit/stderr/expectations, including intentionally invalid JSON nonfinite/duplicate-field fixtures. Those particular `.input.json` files are expected parser-rejection evidence, not asserted strict JSON. All results and successful inputs are strict JSON. Positive/negative cases cover counted-fixed final denominators, unknowns, zero/no pool, secured/impossible, selected unknown others, literal keys, clipping, pair leader losing full field, invalid targets/counts/shares/allocations/keys/overflow. `history/` keeps exact failing bodies and separates source/model defects from checker errors. `validate.py` independently solves clipped roots using linear breakpoint segments, checks every contribution/selected-only threshold/source setting and full candidate/source/priority balance. `reproduce.py` rebuilds in a temporary copy and compares exact outputs. `seal.py` writes final proof then a complete owned manifest excluding only itself; proof does not hash a later manifest. `validate.py --sealed` performs final read-only exact membership/hash/source/link/bounds audit after seal. No git operations or peer mutations are part of reproduction.
