# Delaware turnout research schema and source reconstruction

The priority basis is the 2024 General Election `USSenator` report, all three named candidate rows in every one of 530 election districts. The printed party/candidate strings remain unchanged. The separate declared-write-in list and official tally have no U.S. Senate row; generic/invalid write-ins are unreported, not filled with zero. The report is the claimed official source scope, not an assertion of exhaustive signed/later legal ballot accounting.

`../priority-set.json` is the exact historical dispatch contract. Its 311 `ordered_priority_keys` are the minimum descending 80% set and include the 15 `ordered_top15_keys`; 219 `ordered_remainder_keys` and 530 `full_order` rows retain every Senate district. All percentages use unrounded integer fractions; integer threshold is `(4*500606+4)//5 = 400485`. Sort descending votes then ascending literal ED key. `formal_coordinator_acceptance` and `current_geography_approved` remain false. No current county/ED/polygon crosswalk is granted.

## Main data and disjoint geography

`../../county-turnout.csv` contains 530 **election-district** rows, despite its compatibility filename. One row is an explicit all-candidate zero. Native ID `ElectionDistrict0807` prints `Election District 08-07`; in the explicit county/RD/ED hierarchy RD is `08`, ED `07`. Preserve leading zeros. Use `DE|year|office_key|native_key` across vintages/contests; literal equality does not establish geographic equivalence across years or to November 2026. County FIPS `10001` Kent, `10003` New Castle, `10005` Sussex apply only to parents, not EDs. The retained Census ACS24 county identifier HTML (`census-county-identifiers.body.gz`) verifies those codes; it supplies no election-district geometry.

Main columns: rank, source year/election/office, literal native key/label, county/FIPS and source-evidenced RD/ED, unit kind, three candidate counts, candidate method sums, state/cumulative vote fractions and priority flags. `generic_writein_votes`, `blank_ballots`, `undervotes`, `overvotes`, `ballots_cast` are blank because unavailable in the retained complete products. `participation_voted_2024`, `participation_registered_2024` come from the separate Registered/Voted source; `nov1_registered_2024` is a November 1 stock, blank for absent/sparse native records. They are not interchangeable. Blank never means an invented zero.

County and RD counts are overlapping parent controls. `ByCounty` New Castle is inclusive; `ByCountyW/Wilmington` partitions it into Wilmington and Rest of New Castle. Never add those views together. Wilmington is a municipal component, not a fourth county. Statutory administrative EDs and absent contest tables are explicit in the contract; no central absentee/early board/poll-site/vote-center IDs were supplied by these reports. Method columns are not new geography.

## Required contest extracts

- `../extracts/candidate-rows.jsonl.gz`: 10,699 losslessly compressed candidate rows, covering 2024 Senate/president, 2022 actual House, and 2020 Senate/president in all five views. Fields include `year`, `source_id`, `view`, literal `office_key`, `native_key`, printed `native_name`, heading/table/row offsets, original row index, candidate, party, `raw_fields`, all `cells` (original TD HTML plus labels/text), and parsed integer `numeric` methods. Statewide and RD use their printed identities. County views are wide controls; their `native_key` names the view, with actual county/municipal identities in original column labels. They are not separate additive votes.
- `tables.json`: all 2,674 required-contest tables with raw header labels and positions. `native-inventory.json` inventories **all-office** ED/RD memberships and heading positions without a redundant unrelated-office candidate derivative. The complete original entity bytes retain every unrelated row and field. No original row is discarded from storage.
- `state-controls.json`: every required state-CSV candidate row, source header fields unchanged, one-based CSV row numbers (header row 1). CSV `Early Voting` zero in 2020 is separate from unprinted HTML fields.
- `reconciliation.json`: every candidate/method ED and RD sum against primary state controls. All 3,500 2020 ED candidate early-vote positions are null, not 0; state CSV prints early sums 0. 2020 source `Absentee Votes` includes absentee and vote-by-mail.
- `county-controls.csv`: 60 candidate × county control rows, all three counties, with source row position. Counts are original inclusive-county values. Known-parent ED sums reconcile; the single unparented 2020 presidential vote is not allocated among counties. `unallocated_statewide_candidate_votes` is a statewide candidate scope, not a separate residual to add to each county.
- `historical-rankings.json`, `county-rankings.json`, `method-rankings.json`: full descending counts for each stated context/method; rank only the complete named report universe. Separately published WI totals have no ED allocation.

All HTML character offsets are zero-based, end-exclusive in the full UTF-8-SIG decoded string (BOM omitted if present). Original CR/LF characters remain included; they are **not byte offsets**. The raw entity is retained, so byte positions can be recovered by UTF-8 encoding the prefix, accounting for the BOM. Required candidate row/table positions are independently peer-verified exactly. The original HTML has some unlabeled TD cells and 2022 `Candidate Name`/`Party Name` headings: raw labels remain literal, while the convenience candidate/party fields resolve the documented header variants.

## Original bytes, provenance and acquisition

`original-inputs.json` freezes exact primary-source receipt metadata formerly in the read-only news manifest. Core parser inputs are those **original shared bodies by pinned hash**, not coordinator derivatives. `fresh-*.receipt.json` plus `*.headers.txt` freshly retain complete HTTP redirect header blocks, requested/final URL, UTC start/completion, status, entity/stored SHA-256 and byte lengths. Same entity hashes reuse shared original gzip files via `../../news/…`; no huge original is duplicated. Older prep receipt limitations (no intermediate redirects) are repaired by the fresh receipts, not silently erased.

`acquire.py ID URL PARENT_URL` or `--jobs source/jobs-*.json` makes bounded public downloads. The state results index links the archive; archive links the reports/write-in sheets; each report links its CSV. Candidate and registration archive indexes lead to their exact year products. The source path used for each acquisition is recorded. Some initial sandbox DNS failures have `http_code=0`, `curl_exit=6`, and an empty marker: **no HTTP response entity was acquired**, and these are never data inputs.

All `*.body.gz` or shared `*.html.gz` assets are lossless gzip of complete HTTP content-decoded entities. `gzip.decompress` restores the exact recorded raw hash and byte length. `curl --compressed` decodes HTTP content-encoding before gzip storage; header blocks retain transport metadata. No truncation/simplification/split reconstruction is needed. No object reaches 40,000,000 bytes. The acquisition tool retains even failures as explicit attempts. `render_sources.py` uses temporary exact PDFs only while running Poppler, then removes them. Original PDF bodies remain compressed/referenced.

`../asset-manifest.json` covers every owned file (report/CSV/scripts/data/receipts/peer captures/validation proof) and every used shared original by hash/size, except the manifest itself to avoid a recursive hash. `validation.json` is generated before the manifest; `validate_turnout.py --check` is read-only. Shared originals are read-only and not assigned to this worker's publication ownership. No dependency/cache directory is retained.
