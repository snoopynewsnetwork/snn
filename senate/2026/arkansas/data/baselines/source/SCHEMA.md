# Arkansas baseline package schema and reproduction

The original-only phase is sealed in `../history/original-first/core.tar.gz` with exact member hashes in snapshot.json. It precedes any turnout numerical derivative. `ORIGINAL-FIRST-SCHEMA.md` describes that representation. The subsequent independent peer review is isolated under `../history/peer-frozen`; it never supplies electoral counts to extraction, scenarios or calculators. No peer file is edited. Historical numeric agreement is not coordinator geographic acceptance.

## Acquisition and retained bytes

`original-pins.json` embeds complete individual acquisition receipts and pins exact repo-relative original paths, stored/original SHA256 and sizes. Before every extraction, stored bytes must match. One gzip decompression reconstructs each original response; no truncation/split/normalization is needed. Originals include every unrelated office and source-null field, even though typed derivatives focus on required selected contests. Shared originals remain read-only. All owned files and referenced stored bodies are strictly below 40,000,000 bytes. No dependencies/caches are retained.

Receipts preserve requested/final URLs, parent URLs where returned/discovered, retrieval UTC start/end, response HTTP/curl status and complete original headers/redirect blocks. API lastUpdated, FullData HTTP Last-Modified, actual election date and isOfficial status are independent fields; they do not prove election-night chronology or signed certification. The SOS index → historical shell/linked public JS → appConfig/ClientConfig → ElectionInfo/contest metadata → result/turnout/FullData chain is retained in full. Client route construction is discovery evidence, not vote authority. Source publication comes from the official SOS link and the actual election/status/candidate response.

`current/` retains three DNS failure receipts and complete empty bodies from restricted execution. `network-refresh/` is the successful subsequent original authority-page download. `supplemental/` retains current SOS/candidate page and the published law compilation, each with raw/stored hashes. `original-timeout-pins.json` preserves exact four earlier failed acquisition bodies/receipts and checker evidence by immutable read-only reference. Failure is not a zero electoral observation. `acquire.py` and `acquire_supplemental.py` can refresh public sources, but rerunning those acquisition scripts would overwrite their same-name response artifacts; archive the entire source subdirectory before intentionally refreshing. They are not part of normal offline reproduction.

## Source-native records and types

`candidate-records.csv.gz`: 300,887 positional rows. All selected 2024 president, 2022 Senate, 2020 same-seat Senate and contextual 2020 president candidates survive in separate API/FullData/XLSX lanes. Columns: lane/year/contest/level/county/county_id/native_id/native_name/candidate_id/candidate/party_id/party_literal/method/votes/source_id/position. Votes are integer observed marks, not allocations. Empty CSV fields require the JSON/raw witnesses to distinguish null versus empty source literal. IDs are strings, including leading zeros. Position is the original JSON pointer plus candidate array index, or exact OOXML cell reference. Party literals are never repaired from candidate name or assumptions. 2020 Harrington and 2022 Cates have separate Clerk-confirmed Libertarian identities; partyID1 remains raw unknown. Nevada party metadata is retained verbatim.

API levels state, county, county-native-response and native are overlapping controls, not additive rows. FullData state and county-wrapper/native overlap: Counties repeats each source county once per precinct wrapper. Only one native leaf per position is aggregated. FullData native_id is an array address in candidate-records (not an official ID); native-baselines exposes native_id=null and puts the positional address in the constructed source key. No source candidate ID is deduplicated, and duplicate candidates per native node cause a failure. Complete original objects preserve any outside-field evidence.

`contest-controls.json.gz` retains every selected source node's full raw controls/choice fields (only child geography arrays are omitted because their nodes are separately extracted). Source positions and source_id resolve into original-pins. `candidate-metadata.json` retains selected contest names/IDs, voteFor, candidate name/order/isWriteIn and all raw party/vote-type definitions. `xlsx-president-rows.jsonl.gz` retains the 19,887 rows, exact OOXML row numbers, cell references, t/raw-v values and decoded shared-string values. No duplicate source row is dropped. The 2024 workbook has seven named ballot choices and four additive methods. `total votes` is the control, not a fifth component. API voteType1=All is not Election Day.

`native-inventory.json` stores complete returned API hierarchy and native fields scoped by year/contest_id/county_id/native_id. 2020 ElectionInfo is repeated once for each selected contest, so it is not a disjoint geography sum. A postfreeze representation refinement adds explicit contest_id to these repeated witnesses; the exact earlier representation and script survive in the original-first archive. Actual API native universes are 2,574 (2020), 2,467 (2022), 2,839 (2024). XLSX has 2,841. FullData native keys are source-array positions, separate from API IDs. There is no crossyear or November legal/geometry join.

`turnout-controls.json` retains all 225 complete county responses plus statewide source envelopes, clocks/status/registration/ballots/method fields. Empty native locations and hasLocationTurnout=true both survive. County/native ballot, registration, blank/under/over and eligible named-write-in counts remain null unless explicitly published at that scope. Counted ballots are not contest votes or remaining ballots. Ballots minus candidate votes is not a recovered undervote field. `pdf-controls.json` verifies each of 525 official 2024 county/candidate cells against the independent workbook. `clerk-controls.json` retains each literal matched federal candidate/party control line. `full-api-differences.json` preserves 28 county/candidate differences, including 19 in the three required contests and 9 in contextual 2020 president. No residual is allocated.

`native-baselines.json.gz` groups each source-native/contest leaf's complete candidate vector, original party literals, candidate/method vectors and exact source positions. `../county-baselines.csv` has 675 county/source/contest rows, all 75 distinct parents in each of nine lanes/contests. Complete candidates_json and source_units_json avoid silently grouping non-R as Democratic. A/B identify explicit named pairs; 2020 same-seat A is Harrington (Libertarian), never D. County pair share/margin and all-candidate margin have distinct denominators. Pair weight is defined only in the selected scenario output. Scalar ballots/registration are populated only for matching API/FullData lanes; api_* and full_* columns expose independent source controls even on a workbook row, without assigning native turnout. Blank/under/over remain empty/unknown. Margin bands are absolute pair margin ≤.05, >.05–.10, >.10. They describe historical outcomes.

`independent-complete-orders.json` contains 20 complete shared scopes. Order is descending integer supplied volume then exact source-scoped key ascending; percent encoding is representation, never geographic aliasing. Minimum80 uses 5*cumulative >= 4*denominator with the preceding row failing. Source rows retain zero volume and the entire remainder. `peer-reconciliation.json` compares all shared native/county fields, full 20 orders and all 2,841/75/1,056/1,785 arrays. Representation differences (candidate-cell address vs worksheet/contest-node address, positional FullData keys vs null official native ID) are disclosed; no counts or IDs are imported from peer.

## Historical scenarios and outputs

`scenarios/*.input.json` are complete calculator inputs for 29 scenarios. Each has explicit named pair/complete supplied other field, unit keys, counted zeros, historical all-candidate remaining volumes, per-unit pair participation, pair share and other-candidate allocation. These are historical arithmetic, not estimates of uncounted 2026 votes. When other pool=0, a unit's allocation convention assigns 1 to the first other identity solely to satisfy the numeric schema; multiplied by zero it has no electoral effect. Zero pair volumes have no defined preference. The own-source native/county scenarios retain their own source totals; 2024 is the primary volume basis. The two 2022/2020 named-preference county comparisons explicitly transfer shares/participation to actual 2024 presidential county volumes. No crossyear precinct join exists.

Low/base/high county volumes/mixes are actual 2022 API Senate (901306), 2024 president (1182676), 2020 API president (1219069); 2024 county preference/participation anchors remain fixed. Native low/high uniformly scale the entire 2024 native composition to the historical statewide totals; they do not allocate crossyear county mixes into native units. Four additional 2024 method-mix stresses hold full-contest native preference/participation while using that method's observed all-candidate volumes. This does not infer method-specific remaining preferences or a 2026 effect.

`state-scenarios.csv` has 58 tie/A+1 controls, exact denominators, baseline pair net, unbounded and bounded common-share shifts, clipping counts and final net residuals. Target fractional pair margins are 0/.01. `unit-targets.csv` has 83,690 source-unit/target rows: pair/full volume and weights, participation, share, baseline/target net contribution, gain, net per one share point and selected-only raw/clipped requirement/status. All other units stay at the explicit historical source shares under that scenario's complete volume assumptions. All nonpriority/admin units stay in state sums. Weights and state sums are checked independently; display rounding never enters arithmetic.

## Calculator input/CLI contract

Run `python3 calculator.py INPUT.json` (or `-` for stdin). Standard library only; output is strict JSON. Normal/unknown/no-pool/scenario-impossible return exit0; invalid input returns exit2 with status=invalid-input, clear error and empty stderr. JSON object duplicate fields are rejected by the parser before overwrite. Inputs must be objects with supported keys; mode is historical or live; objective is pair_margin or full_candidate_plurality. Historical mode is an assumption label; supplied counted values are still held fixed, although generated historical inputs use zero counted.

pair is exactly two distinct nonblank string identities; other_candidates lists every distinct other identity with no collisions. units is a nonempty list of objects. Every unit key is a globally unique nonblank string across ALL units, preserving the exact literal key (whitespace only tests blankness), even when an earlier unit has unknown preferences/no pool or a selected key is supplied. selected_unit, when present, must be one of these exact keys. Every counted object supplies exactly every candidate with finite nonnegative numeric counts. Optional counted_total must equal their complete sum; pair counts cannot exceed it. remaining is a finite nonnegative all-candidate pool, pair_participation a finite [0,1] fraction. a_share is finite [0,1] or explicit null=unknown; bool/text do not coerce. other_allocation supplies exactly every named other candidate, finite [0,1], balanced to1; when no other identity exists participation must be1. No hidden generic/write-in allocation is inferred.

target_margin is finite numeric [-1,1] in FRACTION units (not percentage points). Reject bool/null/text/NaN/+Infinity/-Infinity/out-of-range rather than clipping the request. Validate ALL shapes/identities/counts/shares/allocations/settings before arithmetic, unknown/no-pool/selection branches. Aggregate/derived numeric overflow is invalid. Assumptions/source_scope label the intended units/source and remaining-pool assumptions; generated inputs provide both. No probability field exists.

Counted candidates are fixed. Remaining pair pool U=remaining*participation; final pair denominator=counted A+B+sumU; final all-candidate denominator=sum every counted candidate+sum remaining. Remaining A=U*q, B=U*(1-q), others=remaining*(1-participation)*named allocation. Unknown q with U>0 remains unknown; U=0 preference is undefined and has no numerical contribution. Output includes both denominators, both pair/full-field margins and each named candidate's final count when known. Full-field plurality compares A to every named rival, never merely B. It is conditional numerical ordering, not a legal declaration or certified ballot mapping.

For fixed pair weights, unbounded delta=(target*finalPair-baselinePairNet)/(2*remainingPair). This is explicitly a pair benchmark even when full-field objective is selected. Bounded common shift uses clip(q+delta,0,1); evaluates feasible endpoints and solves the monotonic target. Full-field objective targets A-max(rivals)=target*finalAllCandidate. Pair tie/A+1 is not an Arkansas legal outcome rule. No-pool retains fixed-target met/unmet separately; already-secured/impossible endpoints and unknowns survive. selected-only holds every other unit's counted and remaining assumptions fixed; reports raw required shares even <0/>1, corresponding secured/impossible status and clipped display. Unknown OTHER positive-pool preferences make this requirement unknown, while a selected unit's own unknown q can still have an exact conditional threshold.

Set PYTHONDONTWRITEBYTECODE=1. Run extract.py (without --initialize), source_checks.py, build.py, native_discrepancies.py, run_historical_fixtures.py, test_calculator.py, render_report.py, validate.py --write, seal.py, validate.py --sealed. All source controls, candidate sum/uniqueness/coverage, 80% order and state weights remain auditable.

fixtures includes two complete actual historical CLI runs (2,841 primary units and 75 named Libertarian-scenario counties), plus 60 synthetic positive/invalid actual CLI inputs/stdout/stderr and exit receipts, positive and invalid scenarios: unknown/no-pool, zero pair, secured/impossible, selected unknown-other, clipping, negative shifts, final denominator, full-field conflict, nonfinite tokens, global key errors in early-return branches, invalid types/counts/pools/shares/allocations/targets and overflow. Independent hand controls and piecewise interpolation at all -q and 1-q knots validate every state and contribution without importing calculator arithmetic. No random synthetic reporting order calibrates probabilities.

All failing substantive fixtures, if any, retain their exact inputs/results and old calculator.
