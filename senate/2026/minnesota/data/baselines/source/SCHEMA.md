# Minnesota partisanship package schema

Version `mn-partisanship/1.0`. All paths below are relative to `data/baselines/` unless stated. Scripts use Python's standard library; the independent PDF control check also uses Poppler `pdftotext`. No peer/preflight extraction code is imported.

`extract.py` verifies the compressed and uncompressed original SHA-256 hashes, checks ZIP CRC, resolves workbook relationships/shared strings, and extracts the original `Precinct-Results` rows. Source string values, leading zeroes, case, literal `no data`, and zero-vote rows survive. CSV uses UTF-8 and standard quoting. CSV empty means unavailable/empty; numerical source zero is `0`. `source/workbook-context.json` distinguishes physically absent/null native cells and keeps raw non-native cells, address, type, formula, sheet path and original header mapping. Complete original ZIP bytes retain every worksheet, office, style, formula and raw cell. No original is rewritten.

## Original bytes and provenance

`source/shared-originals.json` contains read-only references into `../news/`, original/stored bytes and SHA-256, requested/final URLs, retrieval UTC, HTTP status and headers. Decompress each referenced `.gz` with gzip to reconstruct exact original XLSX/PDF/HTML bytes. File suffix `.html.gz` is legacy storage naming, not content typing. Validate the decompressed magic and CRC. Every original and owned artifact is strictly below 40,000,000 stored bytes; no truncation, splitting or simplification is used.

`source/acquisition.json` describes fresh bounded authority-page requests and their retained compressed bodies. An HTTP 200 Radware challenge is recorded as a challenge, not election evidence. Historical retained metadata and the fresh urllib captures expose final redirect destinations; intermediate redirect headers were not retained by those clients. This is an explicit provenance limitation, not an invented complete redirect chain. `source/publication-observations.json` separately records actual research-web-parser observations, primary page/download chains, source dates and manually checked control values. Web-parser observations are not original HTTP bytes and carry no fabricated raw headers. `acquire.py` verifies shared originals read-only and captures current authority pages, with `--refresh` explicitly replacing only its owned captures.

Official XLSX `Notes` supplies certification/recount dates and the county-canvass status of voter statistics. These differ from retrieval, server headers, ZIP metadata and report dates. 2024 polling signatures/absentee-mail splits have a source warning in Clearwater, Swift and Winona. 2020 duplicate headers survive as `TABMODEL__G` and `TABMODEL__R`; their raw labels and columns remain in context. Historical names/counts do not establish a cross-year/current identity or approved geometry.

## Raw geographic and control tables

- `native-{year}.csv.gz`: one original source row. Unique key `MN:{year}:VTDID:{nine_digits}`. Retains `source_id,election_date,source_sheet,source_row,native_key,county_key,county_fips` and every original column. Source header-to-column mapping resolves any field to its OOXML cell. FIPS comes from the actual Counties sheet. Verification checks `VTDID = FIPS + PCTCODE`; source county names agree case-insensitively with the uppercase reference sheet. Case is preserved in both. `PCTCODE` is unique within county/year. No ballot-style, polling-site, Census VTD, municipal-ID or current-equivalence claim follows.
- `county-controls-{year}.csv`: one FIPS parent, 87/year. Sums required contest and method fields; `native_units` counts all source leaves, including zeroes. `municipal-controls-{year}.csv.gz` groups exact MCDNAME by county/year. Municipal names spanning counties remain separate; no legal municipal ID is invented. The raw all-office native columns are available without interpreting unrelated offices.
- Raw `REG7AM` is registered in precinct at 7AM Election Day; `EDR` includes registrations when voting, including absentee registration and updates, not only new individuals. Their sum is a descriptive composite, not an official current active-registration inventory. `SIGNATURES` counts in-person roster signatures; `AB_MB` is accepted regular/UOCAVA absentee plus mail ballots; `FEDONLYAB`/`PRESONLYAB` have their distinct eligibility scopes. `TOTVOTING` is source number casting ballots. None is candidate vote count. Candidate-by-method votes and central-board identities are unavailable in these workbooks; they are never derived from these administrative fields.
- `source/method-discrepancies.csv` lists every method-sum/TOTVOTING disagreement by source row. Totals are never forced to balance. Candidate totals exceeding TOTVOTING are retained separately in validation. `source/extraction-controls.json` contains statewide sums and source row counts.

## Candidate and baseline tables

`source/candidate-identities.json` transcribes full ballot ticket names, source party, field, primary statewide control, contest role/date and direct official source. DFL remains Democratic-Farmer-Labor; analytical D applies only to that field. LIB, IA, Independent, cannabis parties and other opposition fields remain separate. All required contests actually have DFL candidates; no non-R bucket is relabeled D. Stage is November general plurality; no primary, runoff or RCV electorate is combined.

`candidate-votes.csv.gz` is long by `(contest,level,unit_key,candidate_key)`, preserving one row for each source candidate field, including explicit source zeroes. Fields include source row/field/URL, exact source party, named ballot ticket versus generic write-in scope and `votes`. These alternative county/municipal/native views overlap and must never be added to one another.

`source/named-writeins-2020.csv` holds all 522 independently parsed county/candidate cells from the separate 2020 PDF appendix, including explicit zeroes, original spelling and source text line. It is an overlapping scope, not additional votes. Six named candidates total32 versus generic2261. The2229 difference is unallocated scope, not a claim about individual eligibility. No native allocation is supplied. `source/canvass-2020-reconciliation.csv` checks all957 original county-statistic and filed-candidate/generic-WI values, with original PDF hash and text-line position. Raw source remains the complete PDF.

`../county-baselines.csv`, `native-baselines.csv.gz`, `municipal-baselines.csv.gz` are long by `(contest,unit_key)` at their named level. `A/B` are the named DFL/Republican tickets; `other` is the numerical remainder of all individually retained source candidate fields, not a party identity. `all_candidate_votes = A+B+other`; `pair_votes=A+B`; `pair_participation=pair/all_candidate_votes`; shares are fractions and `*_margin_pp` are percentage points. `net_A_minus_B` is votes. `outcome` compares the named A/B pair only. Separate `all_source_bucket_winner_fields/names` and `all_source_bucket_max_votes` preserve the highest full-field source bucket(s), including ties; zero-total units have no winners. A generic-WI bucket is not an adjudicated eligible individual candidate. `pair_weight` and `all_candidate_weight` use the corresponding statewide contest denominator. `closeness` bands use absolute pair margin ≤5, >5–10, >10pp. Labels describe only that election. `ballots_minus_contest` is arithmetic residual, never an inferred undervote. Blank/under/over or valid-named fields stay unavailable except the separately sourced county2020 named-WI counts. `REG7AM_plus_EDR` is explicitly a composite. Source dates/stages/candidate identities appear in every row. `state-baselines.json` retains integer balances and unbounded pair-shift controls.

## Orders, targets, sensitivities

`{county,native,municipal}-{year}-ranked.csv.gz` preserve complete descending orders, including zeroes, ties resolved by exact key. `priority-contract.json` contains each full order and minimum80 set. Integer crossing is `5*cumulative >= 4*state_total`, with the immediately preceding sum below threshold. County2024Senate is the dispatch basis. It is not a legal geographic approval; actual authority is the external coordinator acceptance publication. No reverse acceptance hash is embedded.

`{county,native,municipal}-targets.csv.gz` key `(scenario,contest,unit_key,target)`. Every statewide scenario contains every unit of its stated geography; parents and leaves are alternative runs. `scenario_all_votes` is an all-candidate contest volume, not ballots. `scenario_pair_votes=T` is that volume times the anchor county pair participation. `pair_weight=T/sum(T)`; `all_vote_weight` uses all-candidate volume. Own historical runs use exact pair integers. Cross-year mix scenarios are county-only because no native crosswalk is approved.

Low=`2022-governor`2510661, base=`2024-senate`3189323, high=`2020-senate`3214256 all-candidate votes. Each of four preference anchors supplies its own unit share and county-specific pair participation. `*-mix-volume` uses each historical county volume directly; `*-volume-2024-fixed-mix` rescales all2024 county volumes uniformly to the low/high historical statewide volume. These are historical sensitivity anchors, never2026 projections. Candidate effects, lower preferences and current electorate behavior are not inferred.

For fractional target pair margin g, unbounded shift is `(g*T_total-M0)/(2*T_total)`. `tie` sets g0; `Aplus1_pair_margin` sets g.01, adding0.5 share pp to the unbounded tie shift. The bounded solver finds delta with `q_i=clip(s_i+delta,0,1)` and `sum T_i(2q_i-1)=g*T_total`. It retains unbounded/bounded shifts, applied unit shift, clipping, zero pools and impossible/unknown inputs. After clipping the difference between the two bounded shifts need not be exactly0.5pp.

Each row keeps baseline/scenario net, weight, target share/margin/net, gain, theoretical `.02*T` gain from1sharepp, separately feasible clipped gain, and selected-unit break-even with every other unit explicitly at its historical share plus the named shift (clipped), holding all volumes fixed. `selected_required_raw_share` is unbounded, and `selected_clipped_share` is display only; statuses preserve already secured/impossible/no-positive-pool. A target for one unit is conditional, not independently necessary. `state-scenarios.json` verifies all64 runs; `state-candidate-scenarios.csv` keeps each candidate's full-field expected totals, including the generic-WI bucket separately. Pair targets do not replace the legal plurality comparison with every eligible individual candidate.

## Offline live calculator

`calculator.py --live INPUT.json` reads a single scenario (or `--case CASE_ID` selects one from a saved scenario list), using distinct A/B candidate names and `units`. Each unit declares unique `key`, a complete identical set of nonnegative `counted` candidate totals, `remaining_all` (number or null), `pair_fraction` in[0,1], `A_pair_share` (raw; explicitly clipped), and `other_distribution` mapping each named remaining opponent to its share of the nonpair remainder. Fractions sum1 when that pool is positive. Missing counted identities, unknown pools/preferences, negative/nonfinite pools and invalid distributions are not filled with zeroes. All other units must be included explicitly or represented by an explicitly scoped residual aggregate.

Counted totals stay fixed. Only stated remainder is forecast. Final pair denominator is countedA+countedB+remainingPair; final all-candidate denominator is allCounted+remainingAll. For a pair target g, required remainder share is `[U + g*(countedPair+U) - countedLead]/(2U)`. The all-candidate cushion uses its separate final denominator. Selected-unit solving fixes all counted votes and every other declared remainder preference/pool. No-pool/unknown/secured/impossible/boundary cases retain their statuses and raw requirements. Supplied named opponents are compared individually in the conditional plurality check; no ballot eligibility is inferred. Synthetic scenarios and bounded-solver cases are arithmetic stress tests, not calibrated probabilities or estimates of votes remaining.

## Reproduction, validation and asset audit

Run `PYTHONDONTWRITEBYTECODE=1 python3 data/baselines/reproduce.py` from this state directory, or invoke the absolute script path from anywhere. It uses retained originals offline. `--acquire` verifies retained acquisition references and fetches missing authority captures. `acquire.py --refresh` explicitly refreshes owned authority captures; changed remote versions require review, never rescaling into old controls. `validation.json` checks extraction identities, source and asset hashes/CRC, all candidate balances, denominators, weights/bounds, all-unit target sums, integer80/order, named-WI scope, live final denominators and edge cases, relative Markdown links and asset-size bounds. `asset-manifest.json` inventories every owned file plus source references; the manifest excludes its own recursive hash. `reconcile_peer.py` audits actual peer files read-only, including source columns/raw context, all shared cells, full orders and contract; it never rewrites peer outputs. Peer before/after hashes are preserved. Research arithmetic acceptance does not approve any2026 reporting identity, collector, cadence, turnout forecast or calibrated Needle.
