# Alabama baseline schema and source contract

Version `AL-partisanship-v1`, observed 2026-10-20 UTC. Scope is the 2024 general presidential contest, 2020 general Class II Senate and 2022 general Class III Senate/midterm, every original native column and all 67 parent counties. Numeric scenarios are conditional historical arithmetic. No current geography approval, probability, collector or 2026 turnout projection is supplied.

## Original bytes, receipts and source positions

- [Original references](original-references.json) and [supplementary references](supplementary-original-references.json) pin complete individual HTTP receipts, requested/final URLs, UTC retrieval, status/headers/redirects, parent chain, original SHA256/bytes and stored ordered parts. A receipt part path resolves from `../../turnout/` relative to this source directory. Concatenate all listed parts in order, then `gzip.decompress` once to reconstruct the complete original entity. Verify each stored part and reconstructed body separately. Original XLS ZIPs and current official PDFs live once under `data/turnout/source/http/`; original canvass/2020-ballot PDFs live once under `data/news/`. No huge duplicate originals.
- `canvass-YEAR.receipt.json` and `ballots-2020.receipt.json` pin individual original news-source bodies by exact original/stored hashes, independent of later mutable aggregate manifests. The `asset` is relative to `data/news/`. The recorded news `bytes` denotes original body size, not compressed size. The 2024 canvass original is 46,116,016 bytes and reconstructs from a 29,769,765-byte gzip; stored artifacts are strictly below 40,000,000.
- Fresh own `http/*.receipt.json` use `stored_path_relative_baselines`, resolved from `data/baselines/`. A hash-identical existing original body is referenced read-only. Other bodies are complete gzip objects under `source/http/`. HTTP headers, transport clocks, source document dates and extraction time remain distinct.
- [Typed workbooks](typed-workbooks.json.gz) is a list of original ZIP members, each with year, literal member/county, FIPS, ZIP/member SHA, member bytes/CRC/time and sheets. Sheet `selected_rows` preserves every cell in the full 208-column source extent for the header, selected contest, registered-voter, ballot and straight-party rows. Each cell is `[xlrd_type, literal_value]`: types 0 empty, 1 text, 2 numeric, 3 Excel date, 4 bool, 5 error, 6 formatted blank. Type 6 is not numeric zero. Row and column indices are 1-based. All source row descriptors (first three typed cells), merged ranges, dimensions and native header positions survive; unrelated numeric office detail remains in the complete original member bytes rather than another required derivative. BIFF formula records retain exact Workbook-stream offsets, 1-based row/column and raw payload hex; cached typed values never pretend to be formula source. No source-field duplicates are dropped.
- [Native observations](native-observations.json.gz) preserves each literal native header, source column/member/sheet/hash, every named/generic candidate row, party and contest literals, typed cells, and complete administrative observations. Candidate rows are positional observations; **row ordinal is never global candidate identity**. Jefferson 2024 explicitly reverses Stein/Oliver order relative to Autauga. Raw source rows never become a dictionary that can overwrite duplicates.
- Native keys are `AL:YEAR:general:5digitCountyFIPS:colNNN:URLencodedLiteralNativeHeader`. The original column number is included. Exact strings and whitespace are preserved; no case/spelling alias for native units. ZIP-member county `StClair` maps explicitly to Census `St. Clair` only for parent FIPS. Header labels do not prove physical precincts, split ballot styles, voting methods, polygons or current IDs. Central/absentee/provisional groups remain separate original columns.
- `reported_contest_votes` sums known named/generic marks; `complete_contest_votes` is null if any constituent candidate cell is unknown. Actual selected native cells in these three original ZIPs are all numeric. County observation candidate rows sum by **literal candidate identity**, not cross-county ordinal. Administrative rows are identified by both contest and field; straight-party and selected-contest under/over rows remain distinct.
- [Canvass county cells](canvass-county-cells.json), [state controls](canvass-state-controls.json) and [disagreements](canvass-xls-disagreements.json) retain PDF page, printed page, page-local text line, exact raw line/label, numeric token, raw character region/interval, type, null and visual override. Complete compressed text and parser warnings remain. Blank Wilcox 2024 Stein, blank Washington 2022 Write-In and dashed Perry 2020 Write-In stay null in PDF scope; explicit XLS zeros are separate observations. Numeric parsing assigns complete tokens by page-local right-edge positions. Complete page visual readings repair damaged OCR in Hale/Winston and clarify Henry; no residual imputation.
- [Ballot/registration controls](ballot-registration-controls.json) contains 201 county and 3 printed statewide observations, exact text line positions and printed percentages. `registered_voters` means the printed field, with active/inactive/as-of status unknown. Party-ballot/straight-party columns are not candidate votes. [Administrative reconciliation](../administrative-reconciliation.json) preserves all native/control differences, unknown cells and missing field rows, without allocating residuals.

## Offline calculator input and arithmetic

`../calculate.py [input-file|-]` reads JSON and writes one strict JSON object to stdout. Valid cases exit 0. Expected malformed input exits 2 with `status: invalid-input`, a clear error and empty stderr. No probability/call is computed. Duplicate JSON object fields are rejected during parsing rather than silently overwritten. Nonfinite JSON tokens are rejected. All validation precedes unknown/no-pool/selected-only returns.

Required top-level fields: `mode` (`historical` or `live`), `candidates`, `pair`, `units`, `target_pair_margin`, nonblank `scope` and `assumptions`. Optional `selected_unit` names an existing exact unit key. Extra settings/fields are unsupported. `target_pair_margin` is a finite numeric fractional margin in [-1,1], never bool/null/text or clipped requested target. Distinct candidate objects require nonblank `id`, `name`, `party`, and `scope` (`named`, `generic_write_in`, `unallocated_other`); IDs and names are distinct, and the pair names two supplied distinct IDs. Every count vector includes all supplied candidates in that order; this supplied-vector requirement does not assert source eligible-write-in completeness.

Every source-unit key must be globally unique, nonblank and a string across all units, including unknown/zero pools and nonselected units. Whitespace is used only to test blankness; literal nonblank strings are not normalized. Each unit is an object with a complete finite, nonnegative candidate count vector. All-candidate totals must cover pair counts; aggregate/derived overflow is rejected.

- Historical units: `key`, `votes`, optional finite nonnegative full `volume` (default sum of source votes). Participation and baseline pair preference derive from the complete source vector. Positive alternative volume cannot be supplied for a zero full-source denominator. A zero pair has null preference.
- Live units: `key`, `counted`, finite nonnegative full `remaining`, finite [0,1] `pair_participation`, `a_share` (finite [0,1] or explicit null unknown), and `other_allocation` covering every supplied nonpair identity. Allocations are finite [0,1], sum to one when a positive other pool exists (floating input sum tolerance 1e-12), otherwise sum zero or one. No unknown positive-pool preference defaults to 0.5.

Counted A/B/other votes remain fixed. Only remaining votes are allocated: pair pool `Uᵤ=remainingᵤ*pᵤ`, other pool `remainingᵤ*(1-pᵤ)`. Final pair denominator is counted A+B plus all U; final full denominator is all counted plus all remaining. A required fractional final pair margin g has target net `g*final_pair_denominator`; the same net/full denominator is reported separately. All-remaining required share is `(g*final_pair − counted_A_minus_B + U)/(2U)`. Selected-only share subtracts all other units' explicitly assumed remaining pair net while preserving all counted votes. Raw negative and >1 requirements remain secured/impossible, not clipped feasible values. Unknown other positive-pool preferences produce unknown selected-only thresholds. No-positive-pool and fixed-target status are separate; a threshold tie is not an election win.

For fixed historical pair weights, unbounded tie shift is `(B-A)/(2(A+B))`; A+1 pair margin adds 0.005 share (0.5 share points). A +0.01 share change adds 0.02 pair-margin/net×pair volume. Bounded common shift solves the continuous clipped sum with bisection; unbounded and bounded shifts remain distinct. The independent validator instead uses exact-rational piecewise breakpoint/slope algebra. Every output unit retains counted/full/remaining inputs, pair participation, source votes, baseline preference, weights, baseline/target/gain net votes, clipping target share, +1 share-point net gain and selected-only raw requirement, where defined. Unknown positive pools remain in the output. Baseline and target full-candidate totals and gaps to other named candidates are distinct from pair thresholds. Generic/unallocated choices prevent legal full-field claims. `legal_outcome_declared` always false.

## Reproduce, validate and seal

Run the commands in the [report](../../../county-partisanship.md). Only `xlrd==2.0.2` and system Poppler `pdftotext` are needed for original re-extraction; calculator/build/CLI fixtures use standard Python. Temporary external dependencies are not retained. Original page images were rendered with Poppler and independently read; raw PDFs/text and explicit visual transcriptions are retained. `acquire.py` optionally rechecks current public pages online with complete receipts; it is not required for offline historical reproduction and does not overwrite originals by name.

`verify_cli.py` saves every actual input/stdout/stderr and exit result, including invalid raw JSON/nonfinite tokens in intentionally `.input.txt` fixtures. All `.stdout.json` are strict JSON. These inputs are deliberately not all valid JSON; never claim otherwise. `validate.py` reopens all 201 original members and selected typed cells, tests literal Jefferson ordering, primary statewide/county/native candidate balances, original and stored hashes, uniqueness/coverage/order/minimum integer 80%, source-null observations, all 20 independently derived bounded roots and contributions/weights/selected thresholds, full denominators, actual CLI outcomes, all parent/peer arrays, ballot/registration controls, links and file bounds. Invalid source controls are preserved as qualified observations, not fixed to pass. `validation.json` records meaningful results and external gates.

`seal.py` writes the final seal then the asset manifest **last**. Manifest scope is exactly the report, county CSV and every file under `data/baselines/**`, excluding **only itself**. Every history, receipt, script, proof, fixture, validation and seal is included. The seal can hash validation; neither seal nor validation reverse-hashes the current manifest, avoiding a digest cycle. `validate.py --audit` then performs a read-only exact membership/hash/size/link audit. No owned writes occur after the final manifest. Each stored file is strictly below 40,000,000 bytes. There are no dependency/cache directories in the owned scope.
