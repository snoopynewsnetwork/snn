# Rhode Island maps schema and source scopes

`source/acquisition-index.json` indexes complete immutable `requests/*.json` objects. Each request records its literal/configured URL, method, configured headers and body (null for GET), parent discovery link, UTC start/end, and every ordered redirect/response/error hop. Each response retains ordered headers, status, raw entity SHA256/bytes and ordered `parts`. Each part is deterministic gzip of a contiguous <=32,000,000-byte raw segment, stored once by compressed hash in `originals/`, strictly below40,000,000 bytes. Concatenating decompressed parts reconstructs exactly the complete original entity; empty entities have an empty list. Transport framing is excluded; no HEAD-only/oversize/HTML/error response is treated as a geographic asset. Exceptions with no response are transport failures. Original initial broad CAPTCHA-substring detection flags are retained; `qa/challenge-review.json` documents incidental scripts versus actual blocked pages. No credentials, login, account or bypass action is used.

`source/directory-observation.json` distinguishes the Secretary municipal directory's web-reader hyperlink observation from the retained direct403 entity. The literal links seed all37 actual priority parents. `source/*edges.json` preserve original href/text/anchor position and selected URL. All incidental header/footer links stay in original HTML; they are not navigation instructions. Earlier discovery selectors and authoring errors are documented in `history/authoring-issues.json`; no original response was replaced. Linked publication scope, acquisition success, geometry coverage and November/legal approval are separate.

The Secretary map hub's complete embedded configuration is `source/sos-maps-hub-embedded.json`; the RIGIS site's embedded configuration is separately retained. Complete app/webmap/item/service/layer entities remain original request objects. The RIGIS service URL was a literal search result, not derived by stripping a thumbnail suffix. Its serviceItemId and layerID came from service metadata. SOS service URL is literally `operationalLayers[1].url` in `sos-webmap-data`.

`source/native-batches.json` (RIGIS) and `source/sos-native-batches.json` (Secretary) enumerate every requested/returned objectID array in source-batch order and native CRS. Both sources have complete service/layer/count/allIDs pre AND post observations. Query fields are exactly f, objectIds, outFields=*, returnGeometry=true, returnZ=true, returnM=true, returnTrueCurves=true; batches<=50. There is no outSR/coordinate transformation, offset paging, geometryPrecision, rounding, quantization, simplify/generalize or source repair. Whole metadata changes are recursively reported, not just extent equality. On this capture both metadata entities are byte-identical pre/post.

`derived/{rigis,sos}-native-features.json.gz` preserves every complete feature object in acquired batch/response order: all attributes, full XY and any Z/M/true-curve objects as returned. It is a parsed JSON derivative, not a substitute for original full response bytes. Numeric lexical spelling remains in originals. Native values parse to Python IEEE754 doubles; each ordered ordinate bit digest is checked in the audit. RIGIS native CRS3438/102730 and SOS3857/102100 remain separate. The two full arrays are unequal, despite both containing416 features with the same municipality counts. All39 source TOWN groups are available; no source child or physical-site identity is established by grouping.

`qa/native-audit.json` records every feature's full attributes, structural counts, status, native bbox, full ordered ordinate IEEE754 hash and scoped single-ring GEOS diagnostics. Null/empty/invalid/open/short/curved geometry is retained; no ring is closed or hole/orphan reinterpreted. Stroke previews include complete available linear ring positions without adding closure; curves/unavailable are excluded. GEOS intersections include only already-closed finite valid single-ring polygons, excluding all multi-ring and invalid originals. Zero positive-area intersections in that subset certifies no broader topology or legal outline. No independent same-vintage legal outline was acquired. NoSHP/DBF/SHX originals were acquired and no binary claims are made. Installed PyShp constructor was fully inspected; its `lines` convenience auto-closes rings and is unused.

No producer imports/writers, mutable newsroom aggregate/helper, active-peer directory discovery or optional coordinator review input is used.
