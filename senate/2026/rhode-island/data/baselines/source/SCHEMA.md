# Rhode Island baseline source and calculator schema

This package is independent original-first research for the 2026 regular Class II assignment. Production inputs are the individually frozen receipts in [inputs.json](inputs.json), plus the explicit later observations in [current-inputs.json](current-inputs.json). No coordinator/peer counts or parsers feed the baseline or scenario builders. [Original-first proof](../witness/original-first-proof.json) predates reciprocal access. The complete initial owned bodies are reconstructable from [pre-peer-bodies.tar.gz](../witness/pre-peer-bodies.tar.gz), indexed by [pre-peer-body-witness.json](../witness/pre-peer-body-witness.json). Later changed implementations and early representations remain in `history/`.

## Original bytes and authority

Each frozen input records its exact requested/final URL, retrieval UTC, status, available response headers/redirect hops, complete original receipt, gzip body path, raw/stored SHA-256 and bytes. Early news receipts do not expose intermediate redirect responses; that gap is not invented. Paths in `inputs.json` are state-relative references to existing shared original assets, individually verified by hash. They are read-only, not a dependency on a mutable aggregate manifest or a receipt-directory glob. Complete response bodies, including HTTP error bodies, remain available. New acquisition receipts are under `source/acquired/`; a DNS failure has no HTTP status or body. Reacquisition uses a new receipt name and never overwrites an observation.

The [technical data index](https://www.ri.gov/election/results/2024/general_election/data/) identifies courtesy technical data and directs reliance to the Board website. The independently acquired [Board historical-results page](https://elections.ri.gov/elections/previous-election-results) links its official-result PDFs and XLSX files. Technical source clocks, PDF clocks, HTTP Last-Modified and ZIP member clocks are distinct; none orders a correction. `chains.json` records literal original anchors and byte positions. The 2022/2024 PDFs print OFFICIAL RESULTS; a separate signed certification instrument was not acquired. No future collector, cadence, ballot ID, geometry or eligible-write-in certification is implied.

The complete short/long archives are retained once, through the original body references. [zip-members.json](zip-members.json) gives every member's archive SHA, ordinal, literal path, size, CRC, stored compression size, header offset, raw member SHA and ZIP timestamp, including directories/Mac metadata. Reconstruct a member by gzip-decompressing the fixed body and reading that exact member from the ZIP. No member was truncated or simplified; no ordered splits are needed. All stored artifacts are strictly below 40,000,000 bytes.

## Fixed-width witness

[field-layout.json](field-layout.json) is machine-readable. Original long records have 263 bytes plus CRLF; short records contain their first 101 bytes plus CRLF. Byte positions below are zero-based, half-open, corresponding to the official [2022 format](https://www.ri.gov/election/results/20220819_data_description.pdf). The [2016 format linked by the actual 2020 index](https://www.ri.gov/election/results/20160902_data_description.pdf) leaves slot 3 unlabeled.

| Field | Bytes | Type/meaning |
| --- | --- | --- |
| contest_code | 0:4 | Literal four-digit source contest code, year/view scoped |
| candidate_code | 4:7 | Literal three-digit source code, never a current candidate ID |
| source_code | 7:11 | Literal four-digit native reporting context |
| votes | 11:17 | Integer printed-candidate or generic-write-in total |
| methods | 17:101 | Fourteen ordered six-byte integer slots; all retained |
| party | 101:104 | Literal padded source label; includes DEM, REP, Ind, Lib, Grn, Ken, Par, S&L, All, `AS `, NON |
| district_type_id | 104:107 | Literal text, including spaces |
| district_code | 107:111 | Literal text, including spaces |
| contest_title | 111:167 | Literal padded title |
| candidate_name | 167:205 | Literal padded name, including source party prefixes |
| source_name | 205:235 | Literal padded reporting name |
| district_name | 235:260 | Literal padded text |
| votes_allowed | 260:262 | Literal source field, selected contests vote for one |
| referendum_flag | 262:263 | Literal source character |

`witness/root-selected.jsonl.gz` contains all 12,997 selected root records. `selected-all-views.jsonl.gz` additionally preserves the complete selected nested/setup rows without adding views. Each record retains the full raw 263-byte record, all parsed fields, 14 slots, original ZIP SHA/member/line/byte_start/byte_end and SHA of the full original line including terminator. Padding is preserved. The whole unused office content remains in the original ZIP, without an unrelated-office derivative requirement. Complete PDF text, XLSX selected cells and literal HTML row positions are also preserved in `witness/`; unused original PDF/XLSX content remains in its complete original body.

Slot descriptions are publication-specific. 2020 format slots 1/2 are Election Day/Mail Ballots; slot 3 is null in the format and Emergency ballots in HTML/Emergency in XLSX. 2022/2024 formats label slots 1/2/3 Election Day/Mail Ballots/Early Voting; HTML says Polling place/Mail ballots/Early Voting. Slots 4–14 are unlabeled, observed numeric values, not absent methods. No current alias or cross-year method equivalence is inferred from position.

## Native and parent coverage

`extracts/native-inventory.json` has 1,459 year-specific contexts: 504 in 2020, 458 in 2022, 497 in 2024. Original selected contest coverage is 2024 Senate 458/president 497, 2020 Senate 465/president 504, and 2022 Governor 454. Four 2022 federal contexts exist only in Board statistics within this selected-contest scope; Governor is unavailable. Every year has 39 municipal parent proofs from literal municipal HTML child links and four separately retained federal administrative contexts when present. The latter are never allocated to municipalities or polygons. Native names, polling-site labels, limited, presidential and federal roles remain distinct. A literal `CENTRAL` label is retained as a role hint; this is not a legal classification of a physical precinct. Original names/labels are not cross-year or current geometry crosswalks.

`data/county-baselines.csv` is a compatibility filename for **2,460 long-form native-contest rows**, not counties. Its key is `(election, source_code)`; an observed row also has `source_unit_key = originalZIPsha#rootMember#firstSelectedContestByte`. The canonical 458 Senate priority keys use first Senate byte, not first presidential byte. Candidate/source/native codes remain separate strings. JSON `null` and CSV empty fields mean unavailable/undefined. Observed integer zero remains zero. In particular, 39 president-only contexts in each presidential year have unavailable Senate fields, and 15 observed 2024 Senate contexts have zero candidate totals. `A_pair_share` is undefined whenever A+B is zero; no neutral 0.5 is supplied.

CSV columns include election/year/contest/comparison role; source key/code/name; parent key/kind; observed; named A/B votes and pair/all-candidate shares/margins; complete candidate JSON with source parties, 14 method counts and byte/line positions; summed method slots; original election registration/ballots/blank; and nullable contest ballots, over/under and valid-named-write-in fields. Those last fields remain null at native level because the source does not supply them there. Election-ballot rows are not relabeled as contest ballots. `extracts/native-baselines.jsonl.gz` is the typed representation.

`extracts/native-statistics.json` preserves every selected Board statistic row's exact sheet/row and method fields. `statistic-coverage.json` enumerates every missing source code. Registration sums match Board controls, but 2022 omits 16 native registration rows, 2024 omits 14, and 2022 has no blank-ballot statistic rows. Registration has no asserted active/inactive status or snapshot date beyond publication evidence. `electorate-ballot-reconciliation.json` retains exact excluded-context ballot scopes. No residual is allocated.

`extracts/parent-baselines.json` supplies municipal/admin candidate controls and complete child maps; `parent-rank-sensitivity.csv` is coarser sensitivity only. `native-priority-contract.json` contains all 458 ordered keys, the minimum integer 80% set, all remainder keys, and 39+4 disjoint child maps. Sort is descending own candidate+generic votes, then ascending first original Senate byte. Priority uses integer `previous_cumulative*5 < statewide_total*4`. Current geography and coordinator acceptance remain false.

## Denominators and historical scenarios

A is the named DEM candidate and B the named REP candidate in each of these actual historical fields. Independent/Libertarian/minor-party candidates retain their own identities; NON generic write-ins are unallocated other votes, never a Democratic coalition or one eligible candidate. All five selected fields and electorates remain separate. Every original candidate total reconciles to the primary statewide controls. PDF total percentages can use contest ballots while technical HTML percentages use candidate+generic votes; those denominator scopes are not substituted.

`scenario-settings.json` is the actual implementation contract. Five repeat-electorate cases use each contest's own original native all-vote volumes, pair participation and A/(A+B). Low/base/high cases hold 2024 Senate native preferences/participation and within-municipality source all-vote weights fixed. Municipal all-vote volume anchors are respectively 2022 Governor, 2024 Senate, and 2020 president; all four federal administrative volumes remain their own 2024 Senate values. The resulting statewide volumes are 359,143 / 491,948 / 517,856; these are declared model sensitivities, not 2026 projections or claims of native cross-year equivalence. Scaling within municipal parents is an explicit scenario assumption, never an allocation of historical source counts.

For pair volume T and other counts O, F=T+O. Unbounded fixed-weight tie shift is `(B-A)/(2*T)` A-share units. A+1 pair margin uses target fraction 0.01, adding 0.005 A-share, i.e. 0.5 share points. The implementation solves `sum(Tu*(2*clip(qu+delta,0,1)-1)) = target*T` with bounded shares; clipping can change the shift. Signed loss allowance and already-winning status are retained. No-positive-pair and unknown-positive-pair cases remain explicit. Net votes, fractional share/margin, share points, margin points and all-candidate margins use different named fields.

`native-targets.csv` gives all-unit volume, participation, weights, baseline/target share/net, gains, clipping, and selected-unit-only thresholds for every scenario/target. `parent-contributions.csv` aggregates contributions, weights and nominal/bounded +1 share-point net gains. `parent-selected-targets.csv` solves each selected municipal/admin aggregate with every other native unit fixed at that scenario's explicit baseline. Negative raw shares are secured under those assumptions; above-one shares are impossible; raw thresholds remain unbounded and are never silently clipped into feasibility. The canonical native priority is unaffected.

## Offline CLI contract

Run `python -B data/baselines/scripts/calculate.py INPUT.json` from the state directory. Inputs/results for actual historical cases are under `scenarios/`; meaningful synthetic live cases are under `scenarios/fixtures/`. The CLI returns strict JSON, code 0 for valid arithmetic and code 2 for invalid input. Invalid numeric-token examples are `.invalid-json.txt`, never claimed as valid JSON.

Both modes require an object, `mode` historical/live, named distinct `pair.A`/`pair.B`, a nonempty `units` array, globally unique nonempty string unit `key`s, optional `selected_unit` matching an existing key, and `target_margin` finite numeric in [-1,1]. Bool/null/text/NaN/Infinity are rejected as targets. `candidate_universe_complete` is a bool. All rows, keys, volumes, shares, allocations and finite positive final all-candidate denominators are validated **before** unknown/no-pool branches. Duplicate JSON properties are rejected. Overflow is invalid.

Historical units require finite nonnegative `pair_volume`, `all_volume >= pair_volume`, `a_share` numeric [0,1] or null, named `others` counts and optional nonnegative `unallocated_other`; other totals must balance F−T. A positive pair pool with null preference is unknown. A zero-pair context retains undefined preference and zero contribution. Uniform roots are clipped, with raw/unbounded and feasible results separate.

Live units require nonnegative counted `{A,B,others,unallocated_other}`, nonnegative all-candidate `remaining`, `pair_participation` [0,1], `a_share` [0,1] or null, `other_shares` [0,1] and optional `unallocated_other_share` [0,1]. A positive non-pair remainder must be fully allocated to named others or explicitly unallocated. Counted votes remain fixed. Only `remaining * pair_participation` receives pair preference. Final pair denominator is counted A+B plus remaining pair; **final full denominator is all counted A/B/other plus all remaining votes**. Unknown positive-pool preference produces null forecasts; zero-pool, secured/impossible and selected-other-unknown statuses are separate. All source-unit keys are checked even without selecting a unit.

For counted lead L and remaining pair pool U, a target fraction m uses required remaining A share `(m*FINAL_PAIR - L + U)/(2*U)`. Selected-unit thresholds hold every other remaining share fixed at its supplied assumption. Undefined divisions remain null; bounds/secured/impossible retain raw thresholds. Other candidates remain separate. Output distinguishes supplied-candidate plurality from full-field result: a complete universe and no unallocated other votes are required for a full-field arithmetic result. No calculator output is an official legal declaration or probability. Rhode Island's [federal plurality rule](https://webserver.rilegislature.gov/Statutes/TITLE17/17-4/17-4-6.htm) requires the largest vote total; a pair tie/cushion cannot replace that legal threshold.

## Reciprocal, reproduction, and seal

`reciprocal/capture-additional.json` and fixed receipt archive/index identify complete captured final peer bodies. `reconciliation.json` compares full raw root/nested/setup selected fields, party/method/header/null/native/statistic/source-position controls, all 458 order keys, exact 80% crossing and complete parent maps. There are 24,249 passing scoped checks and 11 preserved child-label whitespace representation differences. Own # keys and peer colon keys are compared by exact original archive/member/byte tuple. No peer values were imported into the builder, and no peer file was edited. No future peer-byte equality or coordinator acceptance is claimed.

[Reproduction instructions](../REPRODUCTION.md) run independent extraction/build in a temporary tree. `validate.py` checks original/member hashes, counts, candidate/denominator/weight balances, integer priority, native coverage, a separate Decimal piecewise clipping solver, selected thresholds, real CLI fixtures, eight corruption probes, links and size bounds. `validation.json` precedes `final-seal.json`. `asset-manifest.json` is written last and excludes only itself, including report/CSV/scripts/history/witness/proofs/validation/seal and all original references. Validation/seal do not contain a reverse digest of the current manifest. The final read-only audit performs complete body/hash/size/link/source/order checks without later owned writes.

The 2024 write-in scope has an additional substantive representation difference: complete original detail from row 5 sums to 1,227/eight municipal differences, while the captured peer row-6-onward scan sums to 1,226/nine differences. Cranston original sheet7 D5 is `Mario Frioli ` and E5 is `1`; the row and exact XML/member positions remain in [writein-row5-source-proof.json](../extracts/writein-row5-source-proof.json). [Both scopes](../extracts/writein-detail-scope-comparison.json) are retained without changing the peer or omitting a source row. Neither is a legal eligible-name universe.
