# Rhode Island original-first turnout schema

Canonical dispatch is the **458 actual 2024 Senate source codes**, not the 43 parent sensitivity entries. Read [report](../../../turnout.md) and [contract](../priority-set.json). All count fields are integer source values. Empty CSV cells / JSON `null` mean unavailable, never zero. Percentages are derived after integer sums; source percentage strings survive separately.

## Original objects and acquisition

`inputs/original-receipts.json` snapshots the complete literal original receipt objects selected from shared preparation **before independent extraction**. Its `stored_path` is resolved relative to `data/turnout/`; the shared original bodies are read-only references with exact compressed and uncompressed SHA-256 and sizes. No offline build consults the mutable shared news manifest or a peer directory. `acquired/*.receipt.json` contains each actual requested URL, parent ID, final URL, ordered HTTP hops, status, all headers, UTC retrieval, content hashes and byte sizes. Each complete body is deterministically gzip-compressed in a content-addressed `.body.gz` file; `gzip.decompress` reconstructs the exact acquired entity bytes. HTTP transport framing is not part of entity bytes. DNS failures have no response body; exact exceptions are retained in `acquired/failures/`. Earlier HTTP 403 entity bodies remain available.

`source-graph.json` combines source observations and literal hyperlink edges parsed from their original bodies. Parent/child source clocks, HTTP headers, ZIP clocks and PDF run dates are different facts. URLs, timestamps or filenames do not establish a correction sequence. PDF/ZIP originals are retained once, not copied as every extracted member. All stored objects are strictly below 40,000,000 bytes. No truncation, geometric simplification, residual allocation or rescaling is used.

`zip-members.json` inventories every member of all six technical ZIPs with name, raw bytes, SHA-256, ZIP CRC and embedded clock, including unused Mac metadata. Workbook member inventories supply the same controls for the result XLSX and selected write-in XLSX. Complete original XLSX bytes retain all unrelated-office cells, metadata, cached values and formulas. Unrelated offices are not turned into a second derivative research assignment.

## Fixed-width rows

`field-layout.json` gives inclusive one-based byte bounds from the linked format description. Short records contain 101 numeric characters, followed by CRLF. Long records contain those same 101 positions plus text fields through byte 263, followed by CRLF. `all-long-rows.jsonl.gz` preserves **every complete long record in every root, nested results and setup view** across 2020/2022/2024. It includes:

- `source_id`, ZIP `member`, one-based `line`, zero-based `byte_offset`;
- exact `raw_line`, including spaces and original CRLF;
- `key = original_archive_SHA256:member:byte_offset`;
- literal `fields`: contest/candidate/reporting codes, total, all fourteen six-character method groups, party, district type/code, contest title, candidate name, reporting name, district name, votes allowed and referendum flag.

Field values remain raw strings. A separate integer conversion performs arithmetic. Candidate codes are never deduplicated. Short records remain in original ZIP members and are compared byte-for-byte to corresponding long prefixes in source order. Setup/nested/root are separate **nonadditive** views. `selected-root-rows.jsonl.gz` contains the root selected contests, without altering their original keys or fields. `archive-view-comparison.json` retains every selected differing numeric position and all candidate/view vectors; “row count” and “numeric-field count” are explicitly different measures.

## Source publications and controls

`html-controls.json` preserves selected candidate text, party span, total, literal method labels, source SHA and table/row ordinals. Original full HTML supplies every source position. `municipal-hierarchy.json` contains 117 municipality/year parents, with each literal child code/label/URL and original page SHA; no range-based parent inference is used.

`workbook-selected-rows.jsonl.gz` retains selected-contest and all available registration/ballot/blank source rows, every original selected cell address, raw XML scalar/type, decoded value, headers, sheet metadata, row index and original XLSX SHA. XLSX numeric codes such as `101` remain literal in `columns`; same-year matching to fixed-width `0101` is a documented four-character code formatting operation, verified against exact source reporting names and vectors. That is not a cross-year identity or geometry join. Absent cells remain absent. Method zeroes in registration do not define method registration.

`pdf-controls.json` includes exact source ID/SHA, page, line, raw line, source label, percentage and vector for necessary statewide candidate/noncandidate controls. Full PDF bytes and full Poppler layout text are retained or referenced. The 2020 decimal notation `.18`, `.98`, etc. is parsed explicitly. `method-scopes.json` separates each publication's labels. The third 2020 format slot is unlabelled; its HTML/XLSX vector is called Emergency, not aliased to 2022/2024 Early Voting. All fourteen native slots survive; groups 4–14 have null labels.

`candidate-reconciliation.json` preserves all 27 original candidate identities across the five selected contests, every contributing root row key, the sum vector (total +14 groups), independent HTML/PDF controls and exact XLSX and municipal agreement. `state-controls.json` keeps contest candidate totals and statewide PDF under/over/contest-ballot controls separately. Native/municipal under/over and contest-ballot values are null because the acquired candidate exports do not supply them; statewide omissions are never allocated to native units.

`2024-senate-writein-cells.json` preserves every selected D/E source row, including duplicate labels, blanks, subtotal/total rows, cached values, formulas and literal text, for all 39 municipality sheets. These cells are separate from the technical generic bucket. `writein-scope-comparison.json` retains headline/detail discrepancies, without spelling merges, deduplication or legal-eligibility assumptions. The 2020/2022 scanned write-in originals are retained; no fabricated named/eligible roster or native allocation is supplied.

## Native hierarchy and dispatch keys

`native-inventory.json` has separate year-scoped native entries: 2024 497, 2022 458 and 2020 504. The normalized convenience alias is `RI:year:native:literal-code`. It is **not a stable cross-year geographic identity**. Literal original fixed-width names, XLSX names and municipal link/site labels are stored separately. Roles distinguish published precinct context, limited ballot, presidential-only and federal administrative context; none approves a physical polygon.

The 39 municipality keys use the actual published municipal URL slug: `RI:municipality:slug`. Four federal administrative entries (`9001`, `9002`, `9011`, `9012`) remain disjoint under `RI:state`, without municipal allocation or FIPS. Their parent sensitivity convenience keys are `RI:state-admin:code`. Census municipal GEOIDs are ten-character strings (state + county + county subdivision); county FIPS is context, not reporting substitution. Census vintage is 2020 and proves no November 2026 precinct match.

Every native inventory entry carries all available candidate and workbook source row keys, raw fields and methods, parent-link proof and statistic availability. The 39 president-only contexts have `unavailable_in_source` Senate with null total, methods and candidate rows. The 15 zero-total **published Senate contexts** have actual candidate rows with explicit zeroes. These states are not interchangeable. Registration is absent at 14 2024 native and 16 2022 native contexts, while explicit zero registration rows remain values.

`priority-set.json` is the canonical dispatch contract. `complete_descending_order` has exactly 458 rows, each keyed by the **first Senate candidate row's original archive SHA/member/zero-based byte position**. The `native_key`/`native_code` are separate. All three candidate row keys and source fields are retained in `all_source_native_constituents`; the first record is an anchor for a contest/context, not the whole vote total. Descending order uses summed integer candidate+generic votes; ties use the first record byte offset numerically ascending within the same root member. `ordered_priority_keys` is exactly the first 242, containing the top 15. `minimum80` includes the preceding count/votes, crossing key and the complete 216-key remainder. The primary denominator is all 491,948 votes, including four federal-admin entries. Every one of the 497 native contexts and the 39 unavailable Senate cases remains in the contract inventory.

The 43 parent inventory, full child arrays, all-unit order and 21-parent 80% set survive under `municipal_and_administrative_parent_sensitivity`, `parent-sensitivity.json` and `parent-sensitivity.csv`. They are explicitly **not canonical dispatch**. The compatibility filename `data/county-turnout.csv` contains the canonical 458 native rows, with raw source-position keys, counts, all14 summed methods, printed candidate/party fields, ballot/registration/blank fields, null under/over/eligible-WI cells, exact denominator/cumulative values and priority flags. Full unrounded fractions/integer numerator/denominator are retained; display percentages do not determine membership.

`rankings.json` holds independently ordered historical/native and parent sensitivities with their own full orders and source scopes. It never joins 2020/2022/2024 precinct identities. Named printed-only sensitivity excludes all generic write-ins and is not a claim about which write-ins are legally eligible.

## Rebuild, QA, immutable witness and finalization

Use `python3 -B data/turnout/rebuild.py` from this state directory or its repository-root path from the report. It uses only frozen receipts/originals, Python standard library and Poppler, without installation/caches. Network acquisition is separate in `acquire.py`; its snapshot command is one-time initialization, not an offline build dependency. All original receipt paths are exact individual paths; there is no live shared-manifest or peer glob selection.

`validate_turnout.py` defaults to read-only original byte/position/hash, candidate/state/method, hierarchy/native/null/admin, ordering, integer80 crossing/remainder, denominator, corruption, link and object-bound checks. `--write` records pre-seal `validation.json`; final seal/manifest/witness link existence is deferred only during that initial write, then required by the final read-only audit. Tests corrupt missing native units, method totals, absent-Senate nulls, candidate identities, administrative parent allocation, order, threshold and source anchors. They must be rejected.

`history/repair-history.json` records actual failed checks/repairs and original-first scope steering; exact superseded parent-only draft bodies are retained as gzip historical evidence. They are not current dispatch.

`seal_package.py` runs only after reproduction and QA. It freezes complete owned non-original bodies into a deterministic lossless tar+gzip witness and records every full member's hash/size. Original owned content-addressed acquisition bodies and external shared ZIP/PDF/HTML bytes are referenced by immutable exact path/hash/size rather than duplicated. The witness includes their complete source objects through byte-exact reconstructible references. A read-only audit reconstructs every frozen body and verifies every original reference in full. Then a fixed `final-seal.json` pins the witness and validation, followed by `asset-manifest.json` **last**. The manifest includes every owned file (report, CSV, source, scripts, extracts, histories, proof, validation, witness and seal), excluding only itself. It records external original references separately. Validation/seal never reverse-pin the current manifest, so there is no current digest cycle. After that, the final read-only audit must pass with no owned writes.
