# Massachusetts baseline evidence schema

The source of truth is each complete original response entity, reused read-only by exact raw and stored SHA-256. `shared-originals.json` freezes individual launch receipts before peer comparison. Its `shared_path` resolves relative to `data/baselines/`, as implemented in `extract_originals.py`; the launch description's generic “relative to data/” wording is imprecise. No appendable newsroom manifest is a reproduction dependency. Response bytes are transport-decoded entities, losslessly gzip compressed; they are not truncated or simplified. Missing initial receipt redirects, publisher clocks or certification dates remain unknown. `source/http-network/*.receipt.json` retains own requested/final URLs, UTC, redirect histories, HTTP status/headers, sizes and raw/stored hashes. Earlier `source/http/` records preserve sandbox DNS failures; they are not HTTP403 observations. `browser*.json` stores separately labeled research-browser representations, not original document bytes. Direct challenge bodies remain complete evidence of access failures.

`extract/<contest>-original-extraction.json.gz` retains both complete CSVs as arrays of raw row strings, both ragged header rows, one-based CSV record/column ordinals, every candidate/control position, HTML candidate text/party display, overlapping county observations, state footers, and disjoint municipal/native objects. Position counts are 13,735 (2024 Senate), 15,156 (2020 Senate), 16,458 (2022 governor), 30,217 (2024 president). Raw integers are parsed only from printed fields; missing is null and never fabricated zero. Party-row length is not padded. All Others remains unallocated generic scope, separate from every named candidate and Blanks. No deduplication of candidate keys or repair of the2022 HTML discrepancy is performed. Original HTML bytes retain all outside fields without a second extraction of unrelated offices or demographics.

`data/county-baselines.csv` is a compatibility filename containing all9,351 finest printed native contest contexts; `municipal-baselines.csv` is the alternative1,404 parent observations. Their composite uniqueness key is `(contest, scope, source_unit_key)`. `source_unit_key` is compact JSON of the exact `[City/Town,Ward,Pct]` literals. It is not a numeric precinct ID, geometry ID, current feed key or cross-year identity. The calculator's global keys must be unique within each supplied scenario; never combine multiple contests or overlapping parent/child observations. Literal letters, dashes, empty strings, abbreviations and case remain unchanged. `native-hierarchy.json` preserves all351 parents per contest and every literal ward/child grouping. Its118 empty-Ward/Pct2022 objects are sole municipal-granularity source contexts; no missing precincts are invented. No separately identified central administrative/method rows are supplied by these exports. This does not establish their absence in counting.

Baseline fields: `A_votes/B_votes` are the first two named columns with names retained in `A/B`; `other_named_votes` is every remaining named candidate, not a party coalition; `candidate_values_json` retains every printed named candidate separately. `All_Others`, `Blanks` and `Total_Votes_Cast` remain separate raw scopes. `named_candidate_total` excludes generic and blanks; `reported_generic_total` is all named plus generic, not an asserted valid-write-in denominator. `pair_total=A+B`; `pair_participation_reported=pair_total/reported_generic_total`; `pair_participation_ballots=pair_total/Total_Votes_Cast`. Pair share/margin are fractions. `pair_weight` is own-contest pair volume/state pair volume. `baseline_net_votes=A-B`; `gain_net_per_A_share_pp=.02*pair_total`. Method, numeric unit ID, registration and separate under/overvote fields remain null in extraction and empty in CSV, not numeric zero. Source Blanks is not relabeled as a separately observed undervote count. Actual all-zero source rows are retained (12in2024Senate,8in2022Governor,12in2024President). Their baseline shares/denominators are undefined/null; a scenario-only0.5placeholder with T=0 has no arithmetic effect and is not an observed preference. Their selected-only result remains no_positive_pool.

`orders/` has32 complete orders: four contests × two nonadditive scopes × four universes (`named_pair`, `all_named`, `reported_generic`, `ballots`). Named-pair differs from all-named when other named candidates exist. Canonical order is descending integer universe votes, exact City/Town/Ward/Pct lexical tuple, original record ordinal only if needed. `minimum80_member` is the shortest prefix satisfying `5*cumulative>=4*total`; preceding prefix must fail. `priority-set.json` declares primary2024 native Warren+Deaton and alternative scopes; no coordinator/current/legal approval is implied. `scenarios/priority-sensitivity.json` retains alternative ordering/membership impacts and independently derived counterfactual eligibility bounds, not legal allocation evidence.

`scenarios/settings.json` declares18 settings, four own-native anchors, two scaled2024-native volume sensitivities, and four municipal preference anchors crossed with three actual historical municipal pair mixes. Low/base/high pair volumes are2022Governor2,443,746 /2024Senate3,407,108 /2020Senate3,535,574. Native volume sensitivities scale only2024 mix; old municipal votes are never distributed into new native units. Municipal literal same-name comparability is an explicit sensitivity assumption with no boundary approval. Source-reported nonpair participation includes named nonpair candidates plus separate AllOthers. That combined ratio scales the scenario denominator; candidate identities remain in the baseline/extraction, not merged into generic party identities. No2026 volume/preference forecast follows.

Every input gzip is strict JSON with unit `key,T,share,other_votes`. Each setting produces tie and illustrativeA+1pair-margin CSVs for every unit and one state row (36state rows /36,702unit rows). `state_target_pair_margin` is the statewide requested margin; row `target_pair_margin` is the achieved local margin, not the same quantity. `unbounded_target_share` and state unbounded shifts retain the unconstrained formula. Bounded targets use clipped shares and monotone bisection. Raw shifts are fractions; `_pp` means percentage/share points; net votes are separate. `reported_final_denominator=T+sum(other_votes)` excludes blanks. Selected-only fields hold every other unit at the stated unshifted preference anchor and T; raw requirements outside[0,1] remain `already_secured`/`impossible`; clipping does not establish equality. Zero pair pools remain explicit. No pair target replaces full-field plurality.

`calculate.py historical input.json[.gz]` validates all global unit keys, finite nonnegative T/other votes, finite shares[0,1], and finite target margins[-1,1]. `live` requires nonempty unique supplied candidate strings, distinct `A/B`, complete numeric counted/remaining allocation dictionaries and nonempty unique global unit keys. A known `remaining_pool` is `{status:"known",votes:N}`; unknown is `{status:"unknown"}` with no numeric guess. N is remaining candidate votes, not ballots. Allocation shares across the complete field must sum to1. Counted candidates remain fixed; only the stated pool is forecast. Final all-candidate denominator is counted total plus remaining total; final pair denominator is countedA+B plus remainingA+B. Pair target uses that FINAL denominator. The variable pool can be all units or one selected key; every other unit's remaining allocation remains fixed. Full-field strict thresholds compare A to every supplied rival, separately from the pair requirement. Unknown/null outputs denote genuinely unavailable derived results; null numeric inputs are rejected. No probability or lower-preference assumption exists. JSON duplicate keys/NaN/Infinity are rejected; finite-input overflow is a safe error. CLI invalid inputs return structuredJSON and exit2.

`synthetic/` contains11 strict-JSON cases and actual outputs plus65 named arithmetic/type/range/key/JSON checks. No synthetic value is an observed count or calibrated probability. `registration2024-municipal-browser.csv` is347 printed source rows, not351 reconstructed municipalities. Its labels/source line positions are not joined to PD43 abbreviations. `statistics-controls.json` retains all14 registration county controls, statewide dates/definitions, missing labels, unallocated disagreements and separate turnout/method totals. Original registration/method403s limit coverage; no active/inactive split, native allocation or candidate-method preference is inferred.

`source/original-first-freeze.json` and `source/statistics-original-first-freeze.json` are immutable pre-peer witnesses. `peer-audit/` snapshots the actual turnout original-first-v1 bodies compared, with nested gzip preserved when originally gzip, plus exact comparison records. Primary agreement covers full field/order/native coverage/exact80; state statistics agree with a separately qualified additional347row browser extraction. Later peer metadata is not silently treated as audited. Coordinator review is independent and not a build dependency.

`validation.json` records deterministic dataset, arithmetic, source, identity, coverage, link and bounds checks. `final-seal.json` pins the completed report/CSV/validation and immutable witnesses without any reverse manifest digest. `asset-manifest.json` inventories EVERY owned file except itself, including validation and final seal. It also pins read-only reused originals separately. There is no manifest/seal hash cycle. Each stored artifact must be strictly below40,000,000bytes. No dependency/cache directory is retained.
