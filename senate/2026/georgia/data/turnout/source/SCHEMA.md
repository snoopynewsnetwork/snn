# Georgia turnout source and extraction schema

This package ranks **159 disjoint counties**, using the four named options in the official statewide 2024 presidential table. The compatibility filename `county-turnout.csv` is appropriate to this returned county hierarchy; it does not authorize substituting counties for native reporting units. The full qualified-candidate order/shares remain unresolved because most of 858 qualified write-ins have no acquired county allocation. The complete statewide total5,250,905 is corroborated by acquired FEC originals. Compatible Liberty ballot controls prove unique44 and top15 membership without allocation. The worker contract does not assert its own acceptance; the authoritative coordinator decision is external at `data/coordinator-priority-acceptance.json` (relative to Georgia).

## Original bytes and acquisition

`requests*.json` contains exact requested public URLs, the returned parent IDs/slugs from which requests were derived, and parent/source pointers. `scripts/acquire.py` stores each HTTP entity as `source/{id}.body.gz`, with deterministic lossless gzip (`mtime=0`). Recover exact downloaded bytes with `gzip.decompress(path.read_bytes())`; never concatenate different responses. The accompanying `.http.json` preserves request URL, final URL, UTC start/completion, status, all returned headers, redirect chain, entity/stored byte counts and SHA-256 hashes. The Habersham document download uses the actual published read-only POST form and records its exact form body. Failed/challenge responses are retained as such, never relabeled as PDFs or election data.

`shared-references.json` pins four state selected-contest responses already acquired by the coordinator. `source-chain-references.json` pins the retained official index/archive attempts, app shell, main/imported JavaScript, jurisdiction list, metadata/data/selected calls, and blocked original exports/write-in documents. Their `path` is relative to the Georgia directory; these originals are reused read-only, not duplicated. Shared manifest `bytes` means decompressed entity size, while owned HTTP metadata uses `entity_bytes` and `stored_bytes`. Raw and stored hashes are checked independently.

The observed chain is official SOS results index -> linked app -> published main/imported service script -> literal `/results/public/api/elections/{jurisdiction}/{election}/data[/ballot-item/{id}]` template -> returned election IDs -> returned county `shortName` and `parentBallotItemId`. `discover_counties.py` generates exactly 795 county requests: 159 for each of `2024NovGen`, `2020NovGen`, `2021JanFedRun`, `2022NovGen`, and `2022DecGenRun`. The 2020 selected contest ID was independently discovered in `state-2020-data.body.gz`. No election or contest IDs were guessed. Original bodies retain all returned unrelated offices/fields; those are not needlessly flattened into another derivative.

## Keys, positions and missing data

County FIPS is a five-character string from the Census Bureau national county reference. It is joined to the exact English source county name with complete set equality against all 159 Georgia counties. State `locality.id`, child jurisdiction GUID, county election GUID, `parentBallotItemId`, candidate GUID/nativeId, precinct GUID and FIPS are different fields. Candidate `nativeId` is source scoped and cannot serve as a universal candidate key. Exact English display names permit the explicitly checked state/local candidate comparison; 18 nativeId/party differences remain recorded, including blank local party data. All language objects and original types remain in original JSON, and localized native/candidate names are also retained in the extracts.

Array ordinals are zero based. JSON pointers address the original parsed response without deleting, deduplicating or reordering raw source arrays. `source_id` selects an owned `.http.json`/`.body.gz` pair, or `shared:{id}` in the pinned reference manifest. Native keys include election, county FIPS and returned precinct GUID. These keys imply no cross-year or 2026 boundary equivalence.

A blank CSV numeric cell means JSON null or an explicitly unusable/unavailable derived field, never zero. Candidate/method raw Python JSON types are retained (`int`, `NoneType`); values remain unmodified. Raw historic ballot/registration zeros are preserved separately from blank usable fields. These app placeholders are not verified statewide or county zero participation. County 2024 total registration lacks a defined registration-status/snapshot date; active/inactive raw zero fields are not an established split. Blank/undervote/overvote counts remain separate; ballot-minus-candidate differences are not allocated to any of them.

## Extracted tables

- `data/county-turnout.csv` (relative to the Georgia directory): all 159 counties in descending **state named-four** order, integer votes/cumulative totals, exact rational shares, scope-labeled top15/minimum80 flags, separate county all-option total, ballot/registration counts and four historical contest volumes.
- `county-controls.csv`: 795 county-election rows with state/local IDs, scopes, raw and usable ballots/registration, under/over/blank fields, native inventory counts and precise source pointers. Raw all-option votes include Dawson's 19 locally retained disqualified-option votes; statewide named scope excludes those explicitly.
- `candidate-votes.csv.gz`: 15,280 source option rows across `state`, `state_county`, `county`, `precinct`. Preserve source option GUID, nativeId, ordinal, exact name, party identity and write-in flags. These levels overlap and must never be summed together. Each source row exists even when votes are null.
- `candidate-method-votes.csv.gz`: 61,120 source method rows; additionally preserve method GUID/name/ordinal, votes/type and exact method pointer. `votes` repeats the parent candidate total for context; sum `method_votes` only within one disjoint source scope. Methods are components, not extra geographies. Method labels such as `Advanced Voting`, `Advance Voting Votes` and `Election Day Votes` are preserved across elections.
- `native-units.csv`: 2,701 returned 2024 precinct identities, display/localized names, inventory and breakdown positions, status/isVirtual/map fields, source total votes, derived named-scope votes when unredacted, and native turnout/ballot/registration fields. No polling-place rows were returned. Source `isVirtual=false` does not prove that a row has one physical polygon or is not combined. Names containing `Central` are not automatically absentee centers.
- `native-source-total-order.csv`: all 2,701 identities sorted by **county-source all-option native total**, then FIPS/GUID. It is a separate source-total enumeration, not a full qualified-candidate ranking or approved dispatch set.
- `native-candidate-controls.csv`, `native-method-controls.csv`: exact known sums, numeric/null cell counts, parent control and county-minus-known residual. The 40 null candidate cells and 22,416 null method cells remain unallocated. A zero residual with null cells does not authorize filling them with zeros.
- `candidate-crosswalk.csv`: every shared state/local option comparison; retain distinct state/local candidate/native/party IDs, including disagreements. No source candidate keys are deduplicated.
- `method-definitions.csv`: all returned state/county `countGroups` with original positions, group IDs/names and `isFromVirtualPrecinct`.
- `source-clocks.csv`: county election dates, `asOf`, `lastUpdated`, official/production/redaction flags, source IDs and current retrieval. Publication clocks are not certification dates or demonstrated live release cadence.
- `reconciliation.csv`, `state-controls.json`: all-county balances, precise extra-option differences, statewide candidate and method controls, native total coverage and raw/usable control scope.
- `rankings.json`: all five separate statewide contests; complete 159-county order, top15 and exact integer minimum80 crossing/preceding/remainder. Sort is votes descending then FIPS ascending. No cutoff ties occur in these scopes.
- `sensitivity.json`: independent rankings for 2024 county raw all-options, ballots and app registration, plus all four distinct historical contests. These have different denominators and sets; no 2026 turnout forecast is implied.
- `qualified-writeins-observation.json`: explicitly labeled web-parser observation of the separate official certification, not acquired original PDF bytes or a county allocation. `writein-bounds.json` gives membership proof and share uncertainty arithmetic; FEC full-state control and Liberty original ballot bound corroborate the proof. `source/liberty-bound-observation.json` retains eight shown named write-ins (Sonski1 and seven zeros), absent André as unavailable, and generic unresolved0 separately. It never allocates the unclassified108 ballots-minus-reported-votes. `source/fec-georgia-observation.json` pins exact PDF pages/Georgia cells and full statewide5,250,905.
- `priority-set.json`: full 159-county order, named-scope ordered priority/remainder keys and all 2,701 available source-native constituents. Explicit cases cover unavailable historic native rows, polling sites, central/combined/style semantics, qualified write-ins and absent current approval. The contract bytes are frozen in `contract-freeze.json`; `build.py` refuses drift. Its formal-acceptance reference is path only, without an acceptance hash or reverse pin. Full-candidate ordered priority fields are null; proven44 unordered membership and the stable named-four dispatch order are separate. See the source-scoped Liberty observation and FEC full-state corroboration; coordinator acceptance remains separate. Independent peer agreement is distinct from coordinator acceptance.
- `peer-agreement.json`: read-only field-level comparison against the separately extracted actual partisanship worker, with pinned peer input hashes, full orders and native redaction residuals. Agreement on a common original is not independent primary publication.
- `validation.json`, `asset-manifest.json`: meaningful offline checks and hashes of all owned artifacts. The manifest excludes itself to avoid a self-hash cycle and includes external read-only source references separately.

## Reproduce

From the repository root, run `PYTHONDONTWRITEBYTECODE=1 python3 -S senate/2026/georgia/data/turnout/scripts/build.py`, then `compare_peer.py`, `report.py`, and `validate.py` in the same directory. These are offline stdlib scripts; PDF text/preview reproduction uses installed Poppler, as documented in `render_evidence.py`. Acquisition is separate: run `acquire.py` on the retained request lists. Existing receipts are immutable unless a newly named retrieval is deliberately added. No dependencies or cache directories are retained.
